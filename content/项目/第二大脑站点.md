# 第二大脑站点

> [!abstract] 一句话
> 本地 Obsidian 写笔记 → 推到 GitHub `v5` 分支 → Actions 自动用 Quartz 构建 → 发布到 `wiki.dasiwo.com`。

## 部署链路

```mermaid
graph LR
    A[Obsidian 写笔记] --> B[Obsidian Git 插件<br/>自动 commit]
    B --> C{手动 push}
    C -->|分支 v5| D[GitHub Actions<br/>deploy.yaml]
    D --> E[npx quartz build]
    E --> F[上传 public 目录]
    F --> G[GitHub Pages]
    G --> H[wiki.dasiwo.com]

    style C fill:#b7791f,color:#fff
    style H fill:#4b6cb7,color:#fff
```

> [!warning] 唯一需要手动的环节
> Obsidian Git 插件会**自动 commit**（消息形如 `vault backup: 2026-10-10 13:04:35`），
> 但**不会自动 push**。所以每次要公开发布，得手动推一次。

## 常用命令

> [!tip] 必须在仓库根目录执行
> 路径是 `wiki`，不是 `wiki\content`，也不是 `~`

```bash
cd /c/Users/windows/Documents/wiki

# 查看待发布内容
git status
git log --oneline -5

# 推送（首次需绑上游）
git push --set-upstream origin v5
# 之后
git push

# 看本地领先远程多少
git rev-list --left-right --count origin/v5...v5
```

## 踩坑记录

> [!failure] 1. 在 `~` 目录执行 git push
> ```
> fatal: not a git repository (or any of the parent directories): .git
> ```
> 原因：home 目录不是仓库。必须先 `cd` 到 `C:\Users\windows\Documents\wiki`。
> **记住：`~` 里没有 `.git`，仓库在 `Documents\wiki`。**

> [!failure] 2. 推到 `main` 而不是 `v5`
> 这个仓库的默认分支是 **`v5`**（Quartz v5 模板如此），`main` 分支不存在。
> 推 `main` 会新建一个分支，且**不会触发部署**。

> [!failure] 3. 引号未闭合导致终端卡住
> ```
> git config --global user.email "dasiwocom@gmail.com
> > ^C
> ```
> 引号没关，shell 以为命令没结束，进入续行提示符 `>`。按 `Ctrl + C` 取消重来即可。

## GitHub 上的工作流

| 文件 | 作用 | 本仓库是否生效 |
|---|---|---|
| `deploy.yaml` | push 到 v5 → 构建 → 发布 Pages | ✅ 生效 |
| `ci.yaml` | 构建测试 | ❌ 仅上游 `jackyzha0/quartz` 生效 |
| `deploy-v5.yaml` | 发布到 Cloudflare Pages | ❌ 同上 |
| `build-preview.yaml` / `deploy-preview.yaml` | PR 预览 | ❌ 同上 |
| `docker-build-push.yaml` | 镜像发布 | ❌ 同上 |

> [!note] 为什么多数不生效
> 这些 workflow 首行都有 `if: github.repository == 'jackyzha0/quartz'`，fork 出来会被跳过。正常。
