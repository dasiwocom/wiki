# Callout 提示块，全部类型、折叠和嵌套

Callout 是 Obsidian 最好用的一个语法——它能在不打断正文的前提下，把补充内容"挂"在旁边。这篇笔记里你会看到很多个。

## 基本写法

就是引用的第一行加上 `[!类型]`：

```md
> [!note]
> 这是提示块的内容。
```

↓ 渲染出来是这样：

> [!note]
> 这是提示块的内容。

结构拆解：

| 部分 | 作用 |
| --- | --- |
| `>` | 每一行都要有，和普通引用一样 |
| `[!note]` | 只在第一行，决定这个块的类型和图标 |
| 后面的内容 | 块的正文，可以多行，也可以用别的 Markdown 语法 |

## 自定义标题

`[!类型]` 后面直接写字，就是自定义标题：

```md
> [!tip] 一个小技巧
> 内容写在这里。
```

↓ 渲染出来是这样：

> [!tip] 一个小技巧
> 内容写在这里。

不写的话，标题就显示类型名（比如 "Note"、"Tip"）。

只有标题没有正文也行：

```md
> [!warning] 记得先断电
```

↓ 渲染出来是这样：

> [!warning] 记得先断电

## 全部类型

Obsidian 支持的 Callout 类型和别名如下，别名会被自动归一到主类型，图标和颜色都一样：

| 类型 | 别名 | 适合放什么 |
| --- | --- | --- |
| `note` | | 通用的补充说明 |
| `abstract` | `summary` `tldr` | 摘要、"太长不看"版 |
| `info` | | 中性的信息 |
| `todo` | | 待办事项 |
| `tip` | `hint` `important` | 技巧、建议 |
| `success` | `check` `done` | 正确的做法 |
| `question` | `help` `faq` | 疑问、常见问题 |
| `warning` | `caution` `attention` | 需要注意、容易出错的地方 |
| `failure` | `fail` `missing` | 失败案例、错误示范 |
| `danger` | `error` | 危险操作警告 |
| `bug` | | 已知的毛病 |
| `example` | | 示例 |
| `quote` | `cite` | 引文 |

类型写错了不会报错，会退化成 `note` 的样式。所以不用背，用几个常用的就行。

最常用的其实就四个：`note`（补充说明）、`tip`（技巧）、`warning`（注意）、`danger`（危险）。

## 折叠

类型后面加一个符号，就能让它变成可折叠的：

| 写法 | 含义 |
| --- | --- |
| `[!类型]-` | 默认收起 |
| `[!类型]+` | 默认展开 |

两种都能手动点开点关，区别只是初始状态。

```md
> [!question]- 点我展开看答案
> 藏起来的答案。
```

↓ 渲染出来是这样（试着点一下标题）：

> [!question]- 点我展开看答案
> 藏起来的答案。

折叠适合放这些：

- 答案（先让人自己想）
- 冗长的补充（不想打断主线）
- 详细的代码或数据（需要才看）

别把关键结论折叠起来——读者不一定会点开，藏起来等于没写。

## 嵌套

Callout 可以一层套一层，每一层前面多加一个 `>`：

```md
> [!question] Callout 能嵌套吗？
> > [!todo] 能，像这样。
> > > [!example] 还能套更多层。
```

↓ 渲染出来是这样：

> [!question] Callout 能嵌套吗？
> > [!todo] 能，像这样。
> > > [!example] 还能套更多层。

实际写作中套两层以上就很少见了——视觉上会往右缩进太多，读起来费劲。

## Callout 里能放什么

几乎什么都能放：

- 普通的粗体、斜体、代码
- 列表
- 代码块
- 表格
- 图片
- 双链

```md
> [!example] 里面放个列表
> - 第一项
> - 第二项
>
> 还能放代码：`P2 = 0xFE`
```

↓ 渲染出来是这样：

> [!example] 里面放个列表
> - 第一项
> - 第二项
>
> 还能放代码：`P2 = 0xFE`

要注意的是：每一行都要以 `>` 开头。空行也要写成 `>`（后面什么都不写），否则块会断掉。

## 什么时候该用 Callout

Callout 的作用是"插一句，但不打断主线"。判断标准：这段话删掉之后，正文还通不通？

- 删掉也通，但留着有用（补充说明、提醒、例子）→ 用 Callout
- 删掉就不通（是论证的一部分）→ 写成正文

几个典型用法：

| 场景 | 用什么类型 |
| --- | --- |
| "顺便说一句" | `note` |
| "这里有个技巧" | `tip` |
| "这个操作会烧芯片" | `danger` |
| "很多人在这里搞错" | `warning` |
| "先想想再看答案" | `question` + 折叠 |
| "整篇太长，先给结论" | `abstract` / `tldr` |

## Callout 不生效

**只有第一行有 `>`。**

```md
> [!note]
内容没有大于号
```

这样只有第一行在块里，后面的内容跑到外面去了。每一行都要加 `>`。

**`[!note]` 没写在第一行。** 写在第二行就不生效，会变成普通的引用。

**类型和方括号之间多了空格。** `[! note]` 不会被识别。写 `[!note]`，中间不要空格。

**折叠符号写错位置。** `[!note] -`（符号在方括号外面）不生效。要贴着类型写：`[!note]-`。

**用太多。** 一篇笔记里七八个 Callout，视觉上会很吵，正文反而被淹没了。挑真正需要的放。
