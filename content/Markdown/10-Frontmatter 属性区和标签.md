# Frontmatter 属性区和标签

笔记最开头那段被 `---` 上下包起来的内容，叫 frontmatter（也叫属性区、YAML 头）。它不显示在正文里，是"关于这篇笔记的信息"。

## 长什么样

```yaml
---
title: 笔记标题
aliases:
  - 别名一
tags:
  - 标签一
description: 一句话说明这篇讲什么
---
```

几个硬性要求：

- 必须在文件的第一行，前面不能有空行
- 上下各一行 `---`
- 格式是 YAML：`字段名: 值`，冒号后面要有空格

写错任何一条，它就不会被当成属性区，而是变成正文里一堆带冒号的文字。

## 常用的字段

| 字段 | 作用 | 例子 |
| --- | --- | --- |
| `title` | 页面标题（显示在大标题和浏览器标签上） | `title: 我的笔记` |
| `aliases` | 别名，用别的名字也能链接到这篇 | `aliases:`<br>`  - 另一个名字` |
| `tags` | 标签，用来分类 | `tags:`<br>`  - 教程` |
| `description` | 一句话简介，用于分享卡片和搜索结果 | `description: 讲什么的` |
| `draft` | 草稿标记，有些发布工具认这个字段（设为 true 就不发布） | `draft: false` |

列表型字段（`aliases`、`tags`）有两种写法，都行：

```yaml
tags: [标签一, 标签二]
```

```yaml
tags:
  - 标签一
  - 标签二
```

第二种更常见，加新标签时不用动已有的行。

`description` 要写"看完这篇能明白什么"，不要写"本文介绍了……"。前者是给读者的收益，后者是自说自话——它出现在分享卡片和搜索结果里，是别人决定要不要点进来的依据。

## 标签怎么用

标签是跨笔记的分类方式，和文件夹的区别在于：一篇笔记只能在一个文件夹里，但可以有多个标签。有标签功能的工具一般都会自动生成一个标签页，把同一个标签下的笔记收集起来。

标签要写在属性区里。正文里写 `#标签` 在 Obsidian 里能标记，但发布成网页后通常不会变成可点的标签，只会当普通文字显示。

标签命名的几个经验：

- 别太细。一个标签下面只有一篇笔记，等于没分类
- 别太粗。一个标签下面几十篇，等于没分类
- 中文标签完全可以用
- 嵌套标签（如 `教程/Markdown`）Obsidian 支持，用不用看习惯

## 属性区在页面上怎么显示

它不会混进正文。有些发布工具会把属性区渲染成页面顶部的一行信息（标题、标签之类），空着的字段就不显示；有些工具则完全不显示，只把它当元数据用。

所以属性区里的内容，主要是给工具和搜索引擎看的，别指望读者一定看得到。

## 属性区不生效

**属性区不在第一行。** 前面多了一个空行，整个属性区就变成正文了。

**冒号后面没空格。** `title:笔记` 在 YAML 里可能解析失败。写 `title: 笔记`。

**用了中文冒号。** `title：笔记` 不生效。必须是英文冒号加空格。

**缩进用错了。** 列表项前面要空两格，而且必须用空格不能用 Tab：

```yaml
tags:
  - 标签一      # 对：两个空格
- 标签二        # 错：没缩进
```

**值里有冒号。** `description: 什么是 Markdown：一种标记语言` 会被当成嵌套结构而解析失败。把整个值用引号包起来：

```yaml
description: "什么是 Markdown：一种标记语言"
```
