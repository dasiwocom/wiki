# 换行到底怎么回事，回车、两空格、空行有什么区别

在 Markdown 里写东西，最容易让人怀疑人生的一件事就是：我明明按了回车，它为什么不换行？

或者反过来——在 Obsidian 里看着好好的分行，发布到网站上全粘成一坨。

这不是你记错了语法，是 Markdown 里"换行"这件事本身就分三种不同的结果，而它们看起来又很像。

## 三种写法，三种结果

| 你在源码里做了什么 | 页面上得到什么 | 视觉特征 |
| --- | --- | --- |
| 直接按一次回车 | 取决于一个开关，可能换行也可能合并 | 换行了的话，两行贴得很紧 |
| 行尾敲两个空格再回车 | 一定换行 | 两行贴得很紧 |
| 空一行再写 | 一定分段 | 两行之间有明显的空隙 |

最后那一列是区分的关键："换行"和"分段"是两件不同的事，视觉效果不一样——很多人以为自己要的是"换行"，其实想要的是"分段"，也有人反过来。

## 分段：空一行

空一行是 Markdown 里最没歧义的操作。它的意思是：这一段到此结束，下面是新的一段。

```md
这是第一段。

这是第二段。
```

渲染出来是两段文字，中间有一段空白。

那段空白不是你敲出来的，是浏览器给的——每个段落（HTML 里的 `<p>` 标签）默认带有上下间距。所以你会看到，段落和段落之间有明显的空隙，而段落内部的行与行之间只有普通的行距。

这就是为什么你会感觉"有时候有间隔有时候没有"：有间隔的是分段，没间隔的是段内换行。它们是两个不同的东西，不是 Markdown 时灵时不灵。

## 换行：只断行，不分段

有时候你想在同一段之内断开，比如写地址、写诗、写歌词：

```md
北京市海淀区
中关村大街 1 号
100080
```

想要的效果是三行紧挨着，中间不要有段落那种大空隙。

要做到这个，有两种写法。

写法一：行尾敲两个空格。

```md
第一行  
第二行
```

（注意第一行末尾那两个空格，它们看不见，但必须敲。）

写法二：写 `<br>` 标签。

```md
第一行<br>
第二行
```

两种效果完全一样。前者是 Markdown 的原生语法，后者是 HTML，都行。

`<br>` 的好处是看得见，不容易漏；坏处是写多了源码会显得乱。两个空格的好处是干净，坏处是你根本看不出自己敲没敲——这也是它最让人抓狂的地方。

## "硬换行"到底是个什么词

> 硬换行 = 源码里按一次回车，页面上就真的换一行。

它的反面叫软换行：你按回车只是为了让源码看着整齐（比如一行太长，折一下），渲染时不算数，两行会被拼回一行。

"硬换行"这个名字来自 HTML。换行在 HTML 里就是 `<br>` 这个标签，全称是 break——所以"把回车变成 `<br>`"就叫硬换行（hard line break），不变成 `<br>`、只是把两行拼起来的，叫软换行（soft line break）。

Markdown 的两种流派就是在这里分道扬镳的：

| 流派 | 单回车怎么处理 | 谁是这样 |
| --- | --- | --- |
| 软换行派（传统） | 拼回一行，要换行得敲两个空格 | 原始 Markdown 规范、CommonMark、GitHub |
| 硬换行派（现代） | 直接换行 | Obsidian 默认、Notion、微信/知乎编辑器 |

两边都有道理。传统派说：源码换行是为了排版源码，不该影响内容；现代派说：我按了回车就是要换行，你凭什么不给我换。

所以这不是"对的写法"，是"你用的那个工具选了哪一边"。

## 两边默认不一样

同一个文件，在两种工具里打开，效果可能完全不同：

| 环境 | 只按一次回车会怎样 | 由什么决定 |
| --- | --- | --- |
| Obsidian（默认） | 换行 | 设置里的 Strict line breaks，默认关闭，也就是默认硬换行 |
| 标准 Markdown / GitHub | 合并 | 规范本身就是这么定的，要换行得敲两个空格 |

Obsidian 默认硬换行，GitHub 那套默认软换行。两边都不去动，就会出现最让人困惑的现象：

> 在 Obsidian 里看着是分行的一段话，发布到网站上变成了一大坨。

### Obsidian 里怎么改

设置 → 编辑器 → Strict line breaks（中文界面可能叫"严格换行"）。

- 不勾（默认）：硬换行，回车即换行
- 勾上：软换行，遵循标准 Markdown，回车会合并，要换行得敲两个空格

不同版本的界面文字略有差别，搜 "line break" 一般能搜到。

改用哪一边都行，关键是写笔记的编辑器和发布它的平台保持在同一边，否则就会出现刚才那种"看着好好的、发出去粘成一坨"。

### 怎么确认你那边是哪一种

不用猜，写两行字试一下：

```md
aaa
bbb
```

发布后看网页源码（F12 或右键"查看源代码"）：

- 看到 `aaa<br>bbb`，就是硬换行
- 看到 `aaa bbb`，或者两行在同一个 `<p>` 里，就是软换行

## 用硬换行时怎么写

硬换行开着的时候，源码怎么排，页面就长什么样，所以最省心的写法是**一行一句话**：

```md
这是第一句。
这是第二句，跟上一句在同一段里，但另起一行。
这是第三句。
```

上面这三行在页面上会显示成紧贴的三行——因为它们中间没有空行，属于同一段。

想分段，就空一行：

```md
这是第一段，讲一件事。

这是第二段，讲另一件事。
```

这样两句话之间会有明显空隙，读者一眼能看出话题换了。

### 一个要小心的地方

开了硬换行之后，别为了源码好看把一句话折成两行：

```md
这是一句很长的话，写到一半发现太长了
于是我按了个回车继续写。
```

上面这样写，页面上会真的断成两行，看起来就像两句。如果你本来只是想让源码每行短一点，那就别回车——让编辑器自动折行显示就好（Obsidian 里叫"软折行"）。

记住一条就够了：源码里的回车，就是你想让读者看到的换行。

## 什么时候该用哪个

| 你想写什么 | 用什么 | 为什么 |
| --- | --- | --- |
| 普通正文，想换话题 | 空一行分段 | 有空隙，读者知道话题变了 |
| 地址、诗歌、歌词 | 直接回车（硬换行） | 要的就是一行行紧挨着 |
| 英文段落，一行一句 | 直接回车 | 源码好读，页面也分行 |
| 并列的好几条 | 列表 `-` | 有项目符号，语义更清楚 |
| 代码、命令行输出 | 代码块 | 等宽字体，不会丢空格 |
| 表格的单元格里要换行 | `<br>` | 见下面 |

### 关于"英文文章不能换行，只好用列表"

用软换行的工具（比如 GitHub）写英文时，源码里一行一句，发布后全糊成一段。于是很多人退而求其次用列表：

```md
- 第一行
- 第二行
```

这样确实能分行，但代价是多了一堆项目符号，而这些内容根本不是"并列项"，用列表在语义上是错的。

如果用的是硬换行，这个土办法就不需要了：直接回车就行，干净、语义也对。

列表该用在它该用的地方：确实是并列的几条。关于列表的完整写法见 [[04-列表怎么写，嵌套、任务列表和列表里塞内容|列表怎么写]]。

## 表格里的换行是个例外

有一处地方，硬换行和两空格都不管用：表格的单元格里。

表格的一行就是一行，你在源码里怎么写都不会让它变成两行。要换行只能写 `<br>`：

```md
| 项目 | 说明 |
| --- | --- |
| 地址 | 北京市海淀区<br>中关村大街 1 号 |
```

这是为数不多的、`<br>` 不可替代的场景。表格的其它细节见 [[07-表格怎么写，对齐和单元格里的特殊内容|表格怎么写]]。

## 换行和其它语法的配合

几个容易含糊的地方：

- 引用块里：回车会换行。写 `> 第一行` 回车 `> 第二行`，出来是两行紧挨着的。
- 列表项里：想在一个列表项里写两段，把第二段缩进到和文字对齐，中间空一行（缩进的那个空格不会被当成代码块）。
- 代码块里：不受硬换行影响，代码里该几行就是几行，不会被插入多余的 `<br>`。
- 脚注里：同样遵循正文的换行规则。
- 标题里：标题不能换行，一个标题就是一行。
