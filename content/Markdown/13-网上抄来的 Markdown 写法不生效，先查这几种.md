# 网上抄来的 Markdown 写法不生效，先查这几种

Markdown 有很多"方言"。网上教程讲的是 GitHub、Typora、某个博客平台还是 Obsidian，往往不说清楚，照抄过来发现没效果，又不知道是自己写错了还是环境不支持。

这篇整理的是几种看着很流行、实际兼容性很差的写法，每一项都写了会产生什么现象、该用什么替代，省得你再试一遍。

## 兼容性差的清单

| 写法 | 常见现象 | 用什么替代 |
| --- | --- | --- |
| `:smile:` 表情短代码 | 原样显示成一串字符 | 直接粘贴 emoji 字符 😀 |
| 定义列表（`术语` 换行后 `: 定义`） | 变成普通的几行文字 | 表格或列表 |
| 正文里写 `#标签` | 当成普通文字，不会变成可点的标签 | 写在 frontmatter 的 `tags` 里 |
| `^2^` `~2~` 上下标 | 原样显示，且 `^` 容易被当成块 ID | `<sup>` / `<sub>` 标签 |
| `![[xxx.html]]` 嵌入 HTML 文件 | 什么都不显示 | 把 HTML 直接写在正文里 |
| `![[xxx.mp4]]` 嵌入视频 | 什么都不显示 | `<iframe>` 嵌站外播放器 |
| Dataview 查询块 | 只有本机 Obsidian 里能看到，网页上不生效 | 手动维护列表，或者用标签页 |

下面挑几个容易踩的展开说。

## 表情短代码

有些平台支持 `:smile:`、`:tada:` 这种写法，输入短代码自动变成表情。

但这不是标准语法，认不认全看工具：GitHub 这类平台认，很多编辑器会把它原样显示成一串字符，读者看到的是一串带底色的文字，而不是笑脸。

最保险的办法是把 emoji 字符本身粘进去：😀 🎉 ✅

从哪复制？系统自带的 emoji 面板（Windows 按 `Win + .`，macOS 按 `Ctrl + Cmd + 空格`），或者去网上找 emoji 表。

## 定义列表

有些 Markdown 方言支持这种写法：

```md
术语
: 这是术语的解释
```

但它不在 CommonMark 和 GitHub 的规范里，多数渲染器会把它变成两行普通文字——`术语` 是一段，`: 这是术语的解释` 是另一段，冒号还在。

替代方案：

- 解释很短 → 用列表：`- **术语**：解释`
- 要解释好几个术语 → 用表格，两列分别是术语和解释
- 术语很多、解释很长 → 用标题分段，见 [[02-标题怎么用，分级、锚点和页内跳转|标题怎么用]]

## 正文里的标签

在正文里写 `#教程`，Obsidian 这类工具会把它当成标签（能在标签面板里看到）。

但发布成网页后，它通常不会变成可点的标签链接，就是一段普通文字前面带个井号。所以要分类，写在属性区的 `tags` 里最稳，见 [[10-Frontmatter 属性区和标签|Frontmatter 属性区]]。

还有一个风险：行首写 `#` 加空格加文字，等于一级标题。所以不打算用标签功能的话，连写都别写。

## 上下标的方言写法

`^2^` 和 `~2~` 是部分 wiki 系统的写法，通用性很差：

- `^2^` 会被原样显示。更麻烦的是，`^` 在 Obsidian 里是块 ID 的标记符号，写在一行末尾会被当成块编号，可能在别处产生莫名其妙的链接
- `~2~` 原样显示，而且容易和删除线 `~~` 打架

用 HTML 标签，这是哪儿都通用的：

```md
X<sup>2</sup>、H<sub>2</sub>O
```

## 嵌入 HTML 文件和视频

`![[xxx.html]]` 这种"把一个 HTML 文件嵌进来"的写法需要渲染器专门支持，大多数情况下不生效，写了什么都不显示。

替代办法是直接把 HTML 写在笔记正文里——只要渲染器不过滤 HTML，`<svg>`、`<iframe>`、`<details>` 这些都能生效。见 [[12-Markdown 做不到的，直接写 HTML|直接写 HTML]]。

视频同理。本地视频文件（`![[演示.mp4]]`）基本嵌不进来，要么用 `<iframe>` 嵌 B 站这类站外播放器，要么给个外链地址。

## Dataview

Dataview 是 Obsidian 的插件，不是 Markdown 语法。它的查询块长这样：

````md
```dataview
LIST FROM #教程
```
````

在装了插件的 Obsidian 里，它能自动列出所有带某标签的笔记。但网页上没有这个插件，查询不会执行，读者看到的要么是一堆源码，要么是空白。

替代办法是手动维护一个列表，或者用发布工具自动生成的标签汇总页。

同样的道理适用于所有 Obsidian 插件语法——Templater、Excalidraw 这类插件的语法，离开 Obsidian 都不生效。

## 为什么会有这些差异

一句话：Markdown 没有唯一的强制标准。

2004 年的原始规范很简陋，后来各家各自扩展：

- GitHub 搞了 GFM（表格、任务列表、删除线）
- Obsidian 加了双链、Callout、高亮
- 各种 wiki 系统加了上下标、定义列表
- 后来有了 CommonMark 想统一，但只统一了基础部分

所以看到一段"别人能用、我不能用"的语法，第一件事是确认对方用的是什么工具——多半是那个工具自己的扩展。

## 怎么自己验证一个写法

与其猜，不如试：

1. 建一个临时笔记，只写那一小段要测的语法
2. 用你的工具预览一下（Obsidian 切到阅读视图；发布工具就渲染成网页）
3. 看结果。如果渲染成了网页，可以按 F12 看那段文字被包在什么标签里，能看出它到底被当成了什么
4. 测完把临时笔记删掉

比如你想知道 `==高亮==` 生不生效，就去渲染结果里看它是不是被一个带高亮样式的标签包着。

这个方法对所有语法都适用，比翻教程快。
