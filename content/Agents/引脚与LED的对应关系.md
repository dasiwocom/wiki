# 引脚与 LED 的对应关系

## 一句话

板子上每颗 LED 都用一根电线接到单片机的一根引脚；8 根引脚合成一组（叫一个**端口**），正好用一个字节的 8 个位来控制——**一位管一颗灯**。

## 三个词其实是一回事

| 说法 | 是什么 | 对应板子上的东西 |
| --- | --- | --- |
| **位（bit）** | 一个 0 或 1 | 一颗灯 |
| **引脚** | 芯片伸出来的一根线 | 接一颗灯的那根线 |
| **字节（byte）** | 8 个位排成一排 | 8 颗灯合起来 |

可以想成墙上一排 8 个开关，每个开关只管一盏灯。写一次 `P2 = 0xFE`，等于**一次把 8 个开关全拨好**——这就是一行代码能控制 8 颗灯的原因。

## 为什么代码里写的是 P2

51 单片机把 32 根 IO 引脚分成 **4 组、每组 8 根**，分别叫 **P0、P1、P2、P3**（P = Port，端口）。写 `P2 = 0xFE` 就是一次给 P2 这组 8 根引脚下命令。

**至于灯接在哪个口，是板厂画电路板时决定的，不是 C 语言规定的。** 常见的 51 学习板把 LED 接在 P2，板上丝印会写清楚（例如 `P20—P27 ← LED模块`）。

- 灯接在 P2 → 代码写 `P2`
- 假如板厂把灯接在 P1 → 同样的代码就得写 `P1 = 0xFE`

C 语言层面 `P0`、`P1`、`P3` 写法完全一样合法，只是灯没接在那儿，写了不会亮而已。

> [!tip] 通用套路
> 看板子丝印或原理图 → 知道零件接在哪个口 → 代码就操作那个口。以后学按键、数码管、蜂鸣器都是这一套，**不用背，看一眼就行**。

## 为什么写 0 反而亮

学习板上 LED 通常是这样接的：

```
5V → 限流电阻 → LED正极 → LED负极 → 单片机引脚
```

- 引脚输出 **0V（低电平）**：5V 和 0V 之间有电压差，电流从 5V 灌进引脚 → **灯亮**
- 引脚输出 **5V（高电平）**：LED 两头都是 5V，没有压差、没有电流 → **灯灭**

这叫**低电平点亮**（电流灌进芯片，也叫灌电流）。所以在这种接法下：

> **字节里有几个 0，就有几颗灯亮。**

`0xFE` = `1111 1110`，8 位里只有 1 个 0 → 只亮 1 颗。如果想只亮一颗，就必须让 8 位里恰好只有一个 0，这就是选 `0xFE` 而不是 `0x80`（有 7 个 0，会亮 7 颗）的原因。

> [!warning] 这不是通用规则
> 低电平点亮只是**这块板的设计**。换成高电平点亮的板或模块，规律就整个反过来（`0xFF` 全亮、`0x00` 全灭）。拿到任何一块新板，先烧一次 `0xFF` 试试：全灭说明是低电平点亮，全亮说明是高电平点亮。

## 位的顺序为什么看起来是反的

两件事各自由不同的约定决定，谁也没规定要对齐：

1. **数学书写约定**：写数字时低位在右（十进制 254 的个位也在最右）。所以 `1111 1110` 里唯一的 0 是**最低位 bit0**，也就是 **P2.0**，写在**最右边**。
2. **板厂布线约定**：灯的编号 D1~D8 从左到右标；D1 接哪根引脚也是画板时定的（例如普中板把 D1 接到 P2.0）。

一个把最低位写在**右端**，一个把 P2.0 放在**左端**——叠在一起就显得"反"了。换一块板，D1 完全可能接到 P2.7，那时同样的代码就亮在另一端。

**所以不要心算位置。** 三种可靠做法，任选其一：

1. **烧一次**：写 `P2 = 0xFE` 下载进去，哪颗亮那颗就是 P2.0，5 秒确定
2. **看丝印**：板上印的 `P20—P27` 和 `D1—D8` 就是答案
3. **按名字操作某一位**，彻底绕开位序问题（见下）

## 常用取值对照

前提：低电平点亮、D1 接 P2.0、D8 接 P2.7。

| 代码 | 二进制 | 结果 |
| --- | --- | --- |
| `P2 = 0xFE;` | 1111 1110 | 只亮 D1（最左） |
| `P2 = 0xFD;` | 1111 1101 | 只亮 D2 |
| `P2 = 0xFB;` | 1111 1011 | 只亮 D3 |
| `P2 = 0xF7;` | 1111 0111 | 只亮 D4 |
| `P2 = 0xEF;` | 1110 1111 | 只亮 D5 |
| `P2 = 0xDF;` | 1101 1111 | 只亮 D6 |
| `P2 = 0xBF;` | 1011 1111 | 只亮 D7 |
| `P2 = 0x7F;` | 0111 1111 | 只亮 D8（最右） |
| `P2 = 0x00;` | 0000 0000 | 8 颗全亮 |
| `P2 = 0xFF;` | 1111 1111 | 全灭 |

不用背这张表，用到时查一下就行。**换一块板，表的"结果"那一列可能整列反过来**。

## 直接操作某一位（推荐写法）

头文件 `REGX52.H` 里已经把每一位单独起了名字：

```c
sbit P2_0 = 0xA0;   // P2.0 这一位
sbit P2_1 = 0xA1;
...
sbit P2_7 = 0xA7;
```

于是可以完全不碰二进制：

```c
P2_0 = 0;   // 点亮接在 P2.0 的那颗灯
P2_7 = 0;   // 点亮接在 P2.7 的那颗灯
```

意图一目了然，也不受位序和板子方向影响。

## 一个好习惯：main 里加 while(1)

```c
#include <REGX52.H>

void main()
{
    while(1)      // 让程序永远停在这里
    {
        P2 = 0xFE;
    }
}
```

没有 `while(1)` 时，`P2 = 0xFE;` 执行完 main 就结束了，程序会继续往下跑进空白区（俗称**跑飞**）。当前看起来正常只是因为没人再去改 P2。学习阶段就养成套死循环的习惯。
