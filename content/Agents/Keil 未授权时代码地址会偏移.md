# Keil 未授权时代码地址会偏移

## 一句话

未授权（评估版）的 Keil C51 有 2KB 代码体积限制，并且把程序固定放到 **0x0800** 地址开始。于是同样的 C 代码，生成的 hex 排布和正版不一样。

## 现象

烧录软件的「Code Buffer」窗口里，别人的代码是**从 0000h 连续排下来**的，而自己的则是：

```
0000h: 02 08 00        ← 只有一条跳转指令
0003h ~ 07FFh: FF FF ...   ← 一大片空白
0800h: 真正代码从这里开始
```

## 怎么确认是不是这个原因

看编译后生成的 `.m51` 文件（链接清单），里面有明确的一行：

```
RESTRICTED VERSION WITH 0800H BYTE CODE SIZE LIMIT
```

构建日志里的授权信息也会显示为 `LIC=----`（无许可证）。**看到这两处任意一处，就是未授权。**

## 影响有多大

| 方面 | 影响 |
| --- | --- |
| 烧录和运行 | 没有影响，程序照常跑 |
| hex 文件内容 | 排布不同，逐字节对比必然对不上 |
| 可用空间 | 评估版限制 2KB，而常见芯片有 8KB 甚至更多，学习阶段够用 |

> [!warning] 别用「逐字节对比 hex」来验证代码对不对
> 即使 C 源码一模一样，编译器版本、优化等级、授权状态不同，生成的字节也会不同。判断代码对不对，唯一标准是**烧进去看现象**。

## 激活之后会怎么变

地址恢复成正常的连续排布，`.m51` 里那行 RESTRICTED 警告消失，Code Buffer 变成：

```
0000h: 02 00 03   (LJMP 0003)
0003h: 启动代码
...
```

这段开头是编译器加的启动代码（清零内存、设置堆栈，然后跳进 `main`），所以用户代码不会正好从 0000h 开始，这属于正常现象。

> [!note] 重新编译才生效
> 激活之后必须**重新 Build**，并且确认工程设置里勾选了生成 HEX 文件，烧录软件也要**重新打开一次** hex 文件，否则加载的还是旧文件。
