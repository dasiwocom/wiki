### **🚀 阶段三：基础外设实战（第 4 章）**

接下来，我们正式开启 **第四课：操控芯片的“手和脚”——GPIO（通用输入输出）**！

如果说 CPU 是芯片的“大脑”，那 **GPIO（General Purpose Input Output，通用输入输出）** 就是芯片的“手和脚”以及“感官”。芯片要想点亮一个 LED 灯、驱动蜂鸣器，或者读取按键状态、接收传感器信号，全靠 GPIO 引脚。

---

### **1. GPIO 的两大核心功能：输入与输出**

GPIO 引脚的使用主要分为两大方向：

- **输出模式（Output）——“大脑发指令”**：
    - **高电平（1）**：引脚输出约 **3.3V** 的电压（相当于开关接通/送电）。
    - **低电平（0）**：引脚输出 **0V**（接 GND，相当于开关断开/断电）。
    - _典型应用_：控制 LED 灯亮灭、控制继电器吸合、驱动蜂鸣器发声。
- **输入模式（Input）——“感知外界状态”**：
    - 引脚去检测外部电路传过来的电压是高（3.3V）还是低（0V）。
    - _典型应用_：检测按键是否被按下、读取红外/光敏传感器的报警信号。

---

### **2. GPIO 的常见工作模式（初学者必知）**

STM32 的 GPIO 非常强大，每个引脚都可以通过软件配置成不同的工作模式。最常用的有以下几种：

1. **推挽输出（Push-Pull）**：

- **特点**：输出高、低电平的能力都很强，驱动电流大。
- **适用场景**：点亮 LED 灯、驱动大多数数字器件（**最常用的输出模式**）。

2. **开漏输出（Open-Drain）**：

- **特点**：自己只能拉低电平（0V），要输出高电平必须借助外部的“上拉电阻”。
- **适用场景**：多芯片通信总线（如 I²C 总线）或需要匹配不同电压等级的场景。

3. **上拉 / 下拉输入（Pull-up / Pull-down Input）**：

- **上拉输入**：当外部没有信号输入时，引脚默认保持**高电平**。
- **下拉输入**：当外部没有信号输入时，引脚默认保持**低电平**。
- **作用**：防止引脚悬空时受到外界电磁干扰而产生“忽高忽低”的误动作。

---

### **3. 用 C 语言标准库控制 GPIO 的三步法**

在 STM32 标准库中，控制 GPIO 非常规范，只需固定三步：

1. **第一步：开启 GPIO 时钟**

- STM32 为了省电，默认把所有外设的电源/时钟都关掉了。用哪个端口（如端口 A），就得先“通电”： `RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);`

2. **第二步：初始化 GPIO 参数**

- 告诉芯片你要用哪个引脚、什么模式、多快速率（用结构体配置，然后调用 `GPIO_Init`）：

```
GPIO_InitTypeDef g;
g.GPIO_Pin = GPIO_Pin_1;          // 选择 PA1 引脚
g.GPIO_Mode = GPIO_Mode_Out_PP;   // 配置为推挽输出模式
g.GPIO_Speed = GPIO_Speed_10MHz;  // 输出速率 10MHz
GPIO_Init(GPIOA, &amp;g);             // 写入芯片寄存器

```

1. **第三步：控制引脚输出高低电平**

- **点亮/拉高**：`GPIO_SetBits(GPIOA, GPIO_Pin_1);` （引脚输出高电平 1）
- **熄灭/拉低**：`GPIO_ResetBits(GPIOA, GPIO_Pin_1);` （引脚输出低电平 0）

### **第一步：弄懂“输入”和“输出”**

这两个词是站在 **STM32 芯片（大脑）** 的角度来说的：

- **输出（Output）= 芯片控制外界（信号往外走）**
    - **生活比喻**：就像**你的手去按开关、喊口令**。
    - **芯片在干嘛**：芯片的大脑决定“我现在要吐出 3.3V 高电平”或者“吐出 0V 低电平”。

- **输入（Input）= 芯片感知外界（信号进芯片）**
    - **生活比喻**：就像**你的眼睛看、耳朵听**。
    - **芯片在干嘛**：芯片自己不发电，而是闭上嘴巴，静静地“听”外部引脚上的电压是高（3.3V）还是低（0V）。
    - **常见例子**：芯片**读取按键是否被按下**、读取**温湿度传感器的数据**、读取**人体红外感应信号**。

### **第二步：弄懂三种最常用的工作模式**

引脚就像芯片延伸出来的一根导线，为了适应不同的外设，ST 公司给这根导线设计了不同的“工作状态”：

#### **1. 推挽输出（Push-Pull）—— “大力士双向开关”**

- **原理比喻**：引脚内部有两个强力开关，一个连接 **3.3V 电源**，另一个连接 **0V 地线**。
    - 当你要输出高电平时，上面的开关合上，把 3.3V **推**出去（Push）；
    - 当你要输出低电平时，下面的开关合上，把电压**拉**回 0V（Pull）。
- **特点**：驱动能力非常强，能够直接推亮 LED 灯、驱动大多数普通器件。
- **一句话记忆**：**最常用的输出模式，说高就高，说低就低，力气大！**

---

#### **2. 开漏输出（Open-Drain）—— “只能拉低，高电平靠外援”**

- **原理比喻**：引脚内部**只有连接 0V 地线的开关**，没有连接 3.3V 电源的开关。
    - 当你要输出低电平时，开关合上，引脚顺利变成 0V；
    - 当你要输出高电平时，开关断开，但因为内部没接电源，引脚处于“悬空”状态（没人管它）。
    - 如果想让它输出高电平，必须在外面接一颗**“上拉电阻”**（相当于在电路外面挂一根拉绳连到电源上）。
- **为什么搞这么麻烦？**：
    - **防止打架**：当多个芯片的引脚连在同一条总线上时（比如 I²C 总线），如果大家用推挽模式，一个输出高电平，一个输出低电平，就会导致电源和地线直接短路烧芯片！开漏模式就不会短路。
    - **匹配不同电压**：STM32 供电是 3.3V，但如果你想控制一个 5V 的外设，开漏模式外面接个 5V 的上拉电阻就能轻松搞定。
- **一句话记忆**：**用来做多芯片通信或不同电压转换的特殊输出模式。**

---

#### **3. 上拉 / 下拉输入（Pull-up / Pull-down Input）—— “带弹簧的耳朵”**

- **为什么需要上拉/下拉？**： 当引脚配置为“输入模式”时，如果外部什么都没接（这叫“悬空”），这根导线就像暴露在空气中的天线，周围一点点静电或电磁干扰就会让它读取到的电压**忽高忽低（0和1乱跳）**。
- **原理比喻**：
    - **上拉输入（Pull-up）**：引脚内部安装了一个**拉向 3.3V 的弱弹簧**。平时没人碰引脚时，弹簧把引脚拉在**高电平（1）**；当外部按下按键把引脚接地时，电平才被拉低到 **0V（0）**。
    - **下拉输入（Pull-down）**：引脚内部安装了一个**拉向 0V 的弱弹簧**。平时没人碰引脚时，弹簧把引脚拉在**低电平（0）**；当外部传感器发来 3.3V 信号时，电平才变为 **高电平（1）**。
- **一句话记忆**：**给输入引脚加个默认值，防止空气中的电磁干扰导致误报。**

### **1. 代码落地：GPIO 模式在 C 语言中怎么写？**

### **🚀 第五课：芯片的“急救电话机制”——中断与 EXTI（第 5 章）**

在写代码时，如果我们想知道外部按键有没有被按下，最原始的方法是在 `while(1)` 死循环里不停地去读取引脚电平

。

#### **💡 生活化比喻：死等快递 vs 快递员打电话**

- **轮询方式（死循环轮询）**：就像你今天等一个重要快递，你啥也不干，**每隔 5 秒就跑去门口开门看一眼**。这样不仅累死人（消耗 CPU 100% 的精力），而且如果在你两次看门之间发生了其他急事，你根本无法及时响应
- 。
- **中断方式（Interrupt）**：你安心在书房写代码/看书，**当快递员到了，直接按响门铃（触发中断）**。你听到门铃声后暂停手中的工作，跑去开门签收（执行中断服务程序），签收完再回到书房继续看书
- 。

**中断的概念**：CPU 在正常执行程序时，由于内部或外部突发紧急事件，暂停当前程序，转去处理该紧急事件，处理完毕后再返回原来暂停的地方（断点）继续执行

。

---

### **2. 调度总管：NVIC（嵌套向量中断控制器）**

STM32 内部的外设非常多（按键、定时器、串口、ADC 等），它们都可能同时按响门铃。谁先谁后？谁能打断谁？这就需要一个**“总接线员/调度员”**——**NVIC（Nested Vectored Interrupt Controller）**

。

NVIC 主要通过**优先级**来管理中断，STM32 把优先级分成了两种

：

1. **抢占优先级（Preemption Priority）——“强制插队权”**

- 如果 CPU 正在处理一个低抢占优先级的事件（比如按键处理），此时来了一个高抢占优先级的事件（比如烟雾报警），CPU 会**立刻打断**当前的低优先级中断，先去处理紧急的高优先级事件，处理完再回来。这叫**中断嵌套**
- - 。
- **响应优先级 / 副优先级（SubPriority）——“排队优先权”**
- 如果两个中断的**抢占优先级相同**，它们不能相互打断 。但如果它们**同时发生**，响应优先级高的那个可以**优先排队**被处理

1. - 。

#### **🏥 医院急诊比喻：**

- **普通患者**：主程序（`while(1)`）。
- **感冒发烧（抢占优先级 2）**：打断普通患者，进入诊室。
- **心火重危（抢占优先级 1）**：抢占优先级更高！直接打断感冒患者的诊疗，优先抢救。

---

### **3. 外设接口：EXTI（外部中断/事件控制器）**

GPIO 引脚本身只是个传导电平的导线，它自己不懂得“按门铃”。要想让 GPIO 引脚上的电压变化（比如按键按下时电平从高变低）直接触发 CPU 中断，就需要借助 **EXTI（External Interrupt/Event Controller）**

。

- **EXTI 的作用**：专门监测 GPIO 引脚上的电压**边沿跳变** ：
- **上升沿触发**：电压从 0V 变为 3.3V 的瞬间（低 $\rightarrow$ 高）触发中断
- 。
- **下降沿触发**：电压从 3.3V 变为 0V 的瞬间（高 $\rightarrow$ 低）触发中断
- 。
- **双边沿触发**：只要电压发生变化就触发
- - 。
- **GPIO 引脚映射**：STM32F103 的 16 个 GPIO 输入引脚（PA0~~PG0 映射到 EXTI0，PA1~~PG1 映射到 EXTI1……）共享 16 条外部中断线 。同组（如 PA0 和 PB0）同一时间只能选择一个作为中断源
- 。

### **1. 课本对“中断”的定义**

课本第 5.1 节指出：在处理器中，所谓**中断**是一个过程，即 CPU 在执行程序过程中遇到更加紧急的事件（内部或外部的）需要处理时，**暂时中止**当前程序的执行转而去处理紧急事件，处理完毕后**再返回到暂停处（断点）继续执行**原来的程序

。

- **主程序**：CPU 平时正常在运行的代码
- 。
- **中断服务程序（中断服务例程）**：为紧急事件服务的处理程序
- 。

---

### **2. 课本中“抢占优先级”与“响应优先级”的规则**

课本第 5.1 节和第 5.2 节明确说明，STM32 中每个中断都需要预先指定两个优先级

：

1. **抢占优先级（又叫“主优先级”）** ：

- **核心规则**：**数值越小，优先级越高**
- 。
- **嵌套机制**：如果一个低抢占优先级的中断程序正在执行时，发生了一个高抢占优先级（数值更小）的中断，第一个中断就要暂停来响应这个新的中断，这就是课本所说的**中断嵌套**
- - 。
- **响应优先级（又叫“亚优先级”或“副优先级”）** ：
- **核心规则**：**只有在两个中断的抢占优先级相同**时，才比较响应优先级
- 。
- **排队机制**：只要抢占优先级相同，不论它们的响应优先级如何，**都不能相互打断**，正在执行的中断必须等执行完才会响应新的中断信号 。只有当两个抢占优先级相同的中断**同时到达**时，中断控制器才会根据响应优先级高低（数值更小）来决定先处理哪一个

1. - 。

### **3. 用课本原理解解答刚才的思考题**

- 。
- 课本 5.1 节规定：当高抢占优先级的事件发生时，会**打断**正在执行的低抢占优先级中断

1. 。

因此，当 CPU 正在执行**中断 A**（抢占优先级 2）时，突然发生了**中断 B**（抢占优先级 0），CPU 会： 👉 **B) 立刻暂停中断 A，先去执行中断 B，执行完 B 再返回继续完成中断 A**

**。**

这个数字到底是什么

你问的这个“数字”（比如抢占优先级设为 **0** 或 **2**），代表的就是**中断事件的“紧急程度等级”（优先级序号）**。

在日常生活中，我们习惯了“数字越大越厉害”（比如考试 100 分比 60 分好、等级 10 级比 1 级高）。但在 STM32 中，**规则正好相反：数字越小，级别越高、越紧急！**

---

### **1. 这个数字怎么看？（把它想象成“VIP 紧急编号”）**

你可以把这个数字理解为**急诊室挂号单上的“紧急序号”**：

- **0** **号**：最高特权 / 特急件（特级紧急，随时可以强制插队）
- **1** **号**：一级紧急
- **2** **号**：二级紧急
- **3** **号**：三级紧急（相对不紧急）

因为 **0 比 2 小**，所以在芯片眼里，**0 号事件比 2 号事件要紧急得多**。

---

### **2. 课本里的“抢占优先级数字”和“响应优先级数字”有什么区别？**

课本第 5.1 和 5.2 节中，把中断优先级分成了两种数字配置：

1. **抢占优先级（主优先级数字）**—— 决定**“能不能强制插队打断别人”**：

- 如果当前 CPU 正在处理**抢占优先级为 2** 的代码；
- 此时突然来了个**抢占优先级为 0** 的事件；
- 因为 $0 < 2$（0 级的紧急程度高于 2 级），0 号事件拥有**强制插队权**，会立刻打断 2 号事件，这就叫**中断嵌套**。

2. **响应优先级（副优先级数字）**—— 决定**“同时到达时谁先排队”**：

- 只有当两个事件的**抢占优先级数字一模一样**（比如都是 2）时，这个数字才起作用。
- 如果两个事件同时发生，响应优先级数字小的那个（比如 0 级）先排队进去处理，数字大的（比如 1 级）后处理。**但它不能打断正在执行的中断。**

---

- **这个数字是什么？** 它是你给中断设置的**紧急等级（序号）**。
- **记住核心铁律**：**数字越小** $\rightarrow$ **级别越高** $\rightarrow$ **越紧急！**（0 是最高优先级）

1. **数字越小 = 优先级越高**（`0` 级是最高特权）。
2. **抢占优先级相同 = 无法打断**：只要新来的中断和当前正在运行的中断**抢占优先级数字相同**，无论新中断的“响应优先级”数字有多小，都**不能**强制插队打断，必须等当前正在运行的中断处理完毕。

### **📌 举个实际例子巩固：**

假设 CPU 正在执行 **中断 X**（配置为：抢占优先级 **2**，响应优先级 **3**）：

- **情况 1：来了中断 Y（抢占优先级 1，响应优先级 5）**
    - 比较抢占优先级：$1 < 2$（中断 Y 的抢占数字更小，优先级更高）。
    - 结果：**立刻暂停中断 X**，去执行中断 Y（产生中断嵌套）。
- **情况 2：来了中断 Z（抢占优先级 2，响应优先级 0）**
    - 比较抢占优先级：$2 = 2$（抢占优先级数字一模一样）。
    - 结果：**无法打断**！哪怕中断 Z 的响应优先级数字（0）非常小，但因为抢占优先级相同，CPU 会**继续处理正在进行的进程 X**，等 X 处理完后，再轮到 Z。

在 STM32 的标准库中，使用代码配置中断（即配置 NVIC）和配置 GPIO 非常像，都是通过**“填表（填充结构体）再提交（调用初始化函数）”**的方式来完成的。

在课本第 5.2.2 节中，使用 `NVIC_Init` 配置一个中断，主要分为**“先分组，后填表”**两大步骤。

---

### **1. 第一步：先设定全局“中断分组”（全局配置一次即可）**

在设置具体的抢占优先级和响应优先级数字之前，必须先告诉芯片：“请把 4 位优先级寄存器怎么划分？”

我们通常使用 `NVIC_PriorityGroupConfig` 函数来选择分组（比如最常用的**组 2**）：

```
NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2); // 选择优先级分组 2

```

💡 **这是什么意思？**

- 选择 **组 2** 意味着：抢占优先级可以填 **0~3**，响应优先级也可以填 **0~3**。
- 这个函数在整个工程启动时**只需要调用一次**（比如放在 `main()` 函数开头），给所有的中断统一规则。

---

### **2. 第二步：用 `NVIC_Init` 配置具体的中断（四要素）**

课本中定义了一个叫 `NVIC_InitTypeDef` 的结构体，里面只有 **4 个关键成员**（就像一张有 4 个空格需要填的表格）：

|结构体成员变量|简单理解|可以填什么？（举例）|
|---|---|---|
|`NVIC_IRQChannel`|**你是哪种中断？**（中断源通道）|`USART1_IRQn`（串口1）  <br>`EXTI0_IRQn`（外部中断0）|
|`NVIC_IRQChannelPreemptionPriority`|**抢占优先级填几？**|数字 `0 ~ 3`（数字越小越紧急）|
|`NVIC_IRQChannelSubPriority`|**响应优先级填几？**|数字 `0 ~ 3`（数字越小越紧急）|
|`NVIC_IRQChannelCmd`|**开关：开启还是关闭？**|`ENABLE`（开启）/ `DISABLE`（关闭）|

---

### **3. 完整代码模板（以课本 USART1 串口中断配置为例）**

把上面 4 个成员填好后，最后调用 `NVIC_Init(&amp;NVIC_InitStructure)` 提交，代码如下：

```
NVIC_InitTypeDef NVIC_InitStructure;                  // 1. 声明一张“NVIC配置表”

NVIC_InitStructure.NVIC_IRQChannel = USART1_IRQn;     // 2. 指定中断源为：串口1中断
NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1; // 3. 抢占优先级设为 1
NVIC_InitStructure.NVIC_IRQChannelSubPriority = 2;    // 4. 响应优先级设为 2
NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;       // 5. 使能（开启）这个中断通道

NVIC_Init(&amp;NVIC_InitStructure);                       // 6. 把配置表地址传给初始化函数，写入寄存器生效！

```

## **1. 中断硬件架构与 CPU 处理流程**

### **1.1 中断的基本概念与硬执行逻辑**

中断是处理器与外部设备进行异步通信的核心机制

。当外部设备触发紧急事件时，硬件向 CPU 发出中断请求（Interrupt Request, IRQ）

。

CPU 响应中断的**硬件级执行周期**分为 6 个阶段

：

1. **中断请求（IRQ）**：外设或引脚逻辑产生电平跳变，触发中断标志位

- 。
- **优先级判优**：中断控制器（NVIC）根据当前中断的优先级与正在执行的中断比较，决定是否响应
- 。
- **保护断点与现场（Stacking）**：CPU 硬件自动压栈，将当前程序状态寄存器（xPSR）、PC、LR、R12 及 R0~R3 压入栈（SRAM）中保存
- 。
- **获取向量地址（Vector Fetch）**：CPU 根据中断号查**中断向量表**，取得对应中断服务程序（ISR）的入口地址
- 。
- **执行 ISR（Interrupt Service Routine）**：CPU 切换到特权 Handler 模式，执行中断服务函数
- 。
- **现场恢复（Unstacking）与返回**：执行完 ISR 并清除中断标志后，出栈恢复现场，返回主程序断点继续执行

1. 。

---

## **2. 嵌套向量中断控制器（NVIC）深度剖析**

STM32F103 基于 ARM Cortex-M3 内核，内置了 NVIC 控制器

。Cortex-M3 架构可支持多达 256 个中断，而 STM32F103 裁切实现了 **60 个可屏蔽中断通道** 和 **16 个内核中断**，并提供 **16 级可编程中断优先级**

。

### **2.1 NVIC 核心寄存器组**

在标准库结构体 `NVIC_Type`（定义于 `core_cm3.h`）中，映射了以下关键硬件寄存器

：

- **ISER** **（Interrupt Set-Enable Registers）**：中断使能寄存器组。60 个可屏蔽中断分别对应 `ISER`（中断 0~~31）和~~ `ISER`~~（中断 32~~59）的特定位。写 `1` 使能对应中断，写 `0` 无效
- 。
- **ICER** **（Interrupt Clear-Enable Registers）**：中断清除使能寄存器组。写 `1` 禁止对应中断（采用写 1 清零设计，防止“读-改-写”竞争）
- 。
- **ISPR** **/** **ICPR**：中断挂起/清除挂起寄存器组，用于手动置位或清除中断挂起状态
- 。
- **IABR** **（Interrupt Active Bit Register）**：中断激活标志寄存器（只读），为 `1` 表示当前中断正在被 CPU 执行
- 。
- **IPR** **（Interrupt Priority Registers）**：中断优先级配置寄存器组。每个中断分配 8 个 bit，但 STM32 仅使用**高 4 位（bit[7:4]）**来表达优先级
- 。

---

### **2.2 优先级分组与数学分配表**

STM32 将这高 4 位（4 个 bit）划分为**抢占优先级（Preemption Priority）** **和** **响应优先级（SubPriority）**

。控制划分的是系统控制块寄存器 `SCB-&gt;AIRCR` 中的 `PRIGROUP[10:8]` 位

。

通过调用库函数 `NVIC_PriorityGroupConfig(u32 NVIC_PriorityGroup)` 设置分组

：

|分组参数|`PRIGROUP[10:8]`|抢占优先级占用 Bit 数|响应优先级占用 Bit 数|抢占优先级可选范围|响应优先级可选范围|
|---|---|---|---|---|---|
|`NVIC_PriorityGroup_0`|`111`|0 bit|4 bit|无抢占（均为 0）|0 ~ 15|
|`NVIC_PriorityGroup_1`|`110`|1 bit|3 bit|0 ~ 1|0 ~ 7|
|**NVIC_PriorityGroup_2**|**101**|**2 bit**|**2 bit**|**0 ~ 3**|**0 ~ 3**|
|`NVIC_PriorityGroup_3`|`100`|3 bit|1 bit|0 ~ 7|0 ~ 1|
|`NVIC_PriorityGroup_4`|`011`|4 bit|0 bit|0 ~ 15|无响应（均为 0）|

> **嵌套铁律**：只有**抢占优先级数字更小**的中断，才能打断正在执行的低抢占优先级中断（发生嵌套）

。若抢占优先级相同，即使响应优先级更小，也**不能打断**正在执行的中断，仅当二者同时到达时，响应优先级小的优先被响应

> 。

---

### **2.3 `NVIC_InitTypeDef` 结构体成员逐行解析**

标准库在 `misc.h` 中定义了配置结构体

：

```
typedef struct
{
  uint8_t NVIC_IRQChannel;                    // 1. 中断源通道
  uint8_t NVIC_IRQChannelPreemptionPriority; // 2. 抢占优先级
  uint8_t NVIC_IRQChannelSubPriority;        // 3. 响应优先级
  FunctionalState NVIC_IRQChannelCmd;         // 4. 使能控制（ENABLE/DISABLE）
} NVIC_InitTypeDef;

```

#### **配置代码完整实现与寄存器写入过程：**

```
NVIC_InitTypeDef NVIC_InitStructure;

// 配置 NVIC 全局分组为 Group 2（抢占 0~3，响应 0~3）
NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2); [8]

// 填充结构体
NVIC_InitStructure.NVIC_IRQChannel = USART1_IRQn;             // 指定通道：串口1中断 [9]
NVIC_InitStructure.NVIC_IRQChannelPreemptionPriority = 1;     // 抢占优先级 1 [9]
NVIC_InitStructure.NVIC_IRQChannelSubPriority = 2;        // 响应优先级 2 [9]
NVIC_InitStructure.NVIC_IRQChannelCmd = ENABLE;               // 使能该中断通道 [9]

// 写入硬件寄存器（该函数内部会将 priority 计算并写入 IPR 寄存器，并将对应 bit 写入 ISER 寄存器）
NVIC_Init(&amp;NVIC_InitStructure); [8, 9]

```

## **3. 外部中断/事件控制器（EXTI）架构与复用映射**

EXTI 管理着 19 个用于产生事件/中断请求的边沿检测线（EXTI0~EXTI18）

：

- **EXTI 线 0~15**：对应 GPIO 引脚的输入线（PX0~PX15）
- 。
- **EXTI 线 16**：连接到 PVD（电源电压检测）输出
- 。
- **EXTI 线 17**：连接到 RTC 闹钟事件
- 。
- **EXTI 线 18**：连接到 USB 唤醒事件
- 。

---

### **3.1 EXTI 内部硬件框图拆解**

```
                    外部引脚 (GPIO)
                          │
                          ▼
                   [ 边沿检测电路 ] ◄── 上升沿/下降沿选择寄存器
                          │
                          ▼
             软件中断 ──►( 或门 )
                          │
                          ├─────────────────────────┐
                          ▼                         ▼
                    [ 挂起请求寄存器 ]         [ 事件屏蔽寄存器 ]
                          │                         │
                          ▼                         ▼
                   ( 与门 ) ◄── 中断屏蔽寄存器    [ 脉冲发生器 ]
                          │                         │
                          ▼                         ▼
                   送往 NVIC 中断控制器       输出到外设 (如触发 ADC/DMA)
                     (中断路径)                 (事件路径)

```

1. **边沿检测电路**：输入信号经过边沿检测，对比 `EXTI_RTSR`（上升沿）和 `EXTI_FTSR`（下降沿）寄存器，满足条件时输出高电平脉冲

- 。
- **中断路径（Interrupt Path）**：脉冲信号通过或门后进入挂起请求寄存器（`EXTI_PR`）置 `1` 。若中断屏蔽寄存器（`EXTI_IMR`）对应位为 `1`，则信号送入 NVIC 请求 CPU 执行 ISR
- 。
- **事件路径（Event Path）**：信号通过与门进入脉冲发生器，若事件屏蔽寄存器（`EXTI_EMR`）允许，直接向芯片内部外设（如 ADC、DMA）产生硬件脉冲，**完全不需要 CPU 参与，响应速度更快**

1. 。

---

### **3.2 AFIO 外部中断引脚映射机制**

STM32F103 的 GPIO 口每 16 个引脚（PAx~PGx）分为一组，但同一编号的引脚（例如 PA0、PB0、PC0...）**共享同一个 EXTI 线（EXTI0）**

。

这种多路复用通过复用重映射寄存器 `AFIO_EXTICR1 ~ AFIO_EXTICR4` 控制

：

```
PA0 ──┐
PB0 ──┼──► [ AFIO_EXTICR1 的 EXTI0[3:0] ] ──► EXTI0 线 ──► NVIC (EXTI0_IRQn)
PC0 ──┤
... ──┘

```

因此，**PA0 和 PB0 不能同时作为外部中断源使用**，同一时间 EXTI0 只能选择 PA0~PG0 中的某一个

。

## **4. 实战案例：中断方式按键控制 LED（完整代码与执行流）**

。

### **4.1 初始化配置代码（`exti.c`）**

```
#include "includes.h" [13]

void EXTIKeyInit(void)
{
    EXTI_InitTypeDef Exti_InitStruct;

    // 1. 初始化 GPIO (以 PB0 作为按键输入为例)
    KeyInit(); // 内部将 PB0 配置为 GPIO_Mode_IPU（上拉输入，平时高电平，按下低电平）[3, 13]

    // 2. 开启 AFIO 复用功能时钟 (EXTI 映射依赖 AFIO)
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO, ENABLE); [13]

    // 3. 将 GPIO PB0 映射到 EXTI 线 0
    GPIO_EXTILineConfig(GPIO_PortSourceGPIOB, GPIO_PinSource0); [13]

    // 4. 配置 EXTI0 结构体
    Exti_InitStruct.EXTI_Line = EXTI_Line0;             // 选择 EXTI 线 0 [13]
    Exti_InitStruct.EXTI_Mode = EXTI_Mode_Interrupt;    // 设置为中断模式（而非事件）[13]
    Exti_InitStruct.EXTI_Trigger = EXTI_Trigger_Falling;// 下降沿触发（按下按键从高变低）[3, 13]
    Exti_InitStruct.EXTI_LineCmd = ENABLE;               // 使能该 EXTI 线 [13]
    EXTI_Init(&amp;Exti_InitStruct);                        // 写入 EXTI 寄存器 [13]

    // 5. 配置 NVIC 优先级
    NVIC_EnableIRQ(EXTI0_IRQn);                         // 使能 EXTI0 中断通道 [13]
    NVIC_SetPriority(EXTI0_IRQn, 5);                    // 设置优先级 [3, 13]
}

```

---

### **4.2 中断服务函数（ISR）硬件响应与标志位清除**

当按键按下，PB0 产生下降沿，硬件置位 `EXTI_PR` 的 bit 0，并触发 NVIC 调用中断服务函数 `EXTI0_IRQHandler`

。

> **注意**：中断服务函数的名称（如 `EXTI0_IRQHandler`）在启动文件（`startup_stm32f10x_xx.s`）的中断向量表中已被预先固定定义，**拼写必须完全一致**

> 。

```
void EXTI0_IRQHandler(void)
{
    // 检查 EXTI0 标志位是否真的置位
    if (EXTI_GetITStatus(EXTI_Line0) != RESET) [3]
    {
        // 业务逻辑：翻转或点亮 LED
        LED(1, LED_ON); [3]

        // 关键步骤：清除 EXTI 挂起标志位（向 EXTI_PR 写 1 清零）
        // 如果不清除标志位，退出中断后 CPU 会认为中断依然存在，导致无限死循环反复进入中断！
        EXTI_ClearITPendingBit(EXTI_Line0); [3]
    }
}

```
