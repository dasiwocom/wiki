# 页面打开不对，先查这几种

HTML 不报错。写错了浏览器也照常显示，只是显示得不对。所以排查得靠"现象 → 原因"。

## 先学会开 F12

浏览器里按 `F12`（或右键 → 检查），面板里两个地方最常用：

**Elements（元素）**：看浏览器实际拿到的 HTML。你写的和这里显示的不一样，说明是浏览器自己修过了，多半是标签没闭合。

**Console（控制台）**：看报错。红色的一行就是出错的地方，点右边能看到出错的文件和第几行。

排查 HTML 问题，九成靠这两个面板。

## 中文变问号或方块

原因是编码声明和文件实际编码不一致。

按顺序查：

1. `<head>` 第一行有没有 `<meta charset="UTF-8">`
2. 编辑器另存为时编码选的是不是 UTF-8
3. 编辑器右下角显示的编码是不是 UTF-8

三处统一成 UTF-8，问题就没了。

VS Code 里如果右下角显示 GBK，点它选"通过编码保存"再选 UTF-8。

另一个不太常见的原因：服务器响应头里声明了别的编码，覆盖了页面的声明。这种情况在浏览器开发者工具的 Network 面板里能看到响应头。

## 图片裂开

一张图片位置出现一个小方块加一个裂图标，或者干脆显示 alt 文字。

按顺序查：

1. **路径对不对**。最常见的是路径写错，或者图片没跟着上传上去
2. **大小写**。本地 Windows 不区分，服务器区分。`Photo.jpg` ≠ `photo.jpg`
3. **文件名有没有空格或中文**。能显示也可能，但复制时容易被转义弄乱
4. **相对路径的基准**。`images/a.png` 是相对于当前 HTML 文件，不是相对于网站根目录。要相对根目录，写成 `/images/a.png`

在 F12 的 Network 面板里刷新一下，能直接看到 404 的那张图，以及浏览器实际请求的完整地址——一对比就知道路径错在哪。

## 标签没生效，页面上直接显示了源码

出现形如 `<p>这是一段</p>` 的文字显示在页面上，通常是两个原因：

**① 忘了闭合**。写了 `<strong>` 没写 `</strong>`，后面的内容全被包进去，甚至整页样式崩掉。

**② 内容里写了尖括号但没转义**。想显示"`<p>` 这个标签"，得写成 `&lt;p&gt;`（见 [[04-文字变了样，加粗、斜体、上下标和实体字符|文字强调和实体字符]]）。

还有一种情况：标签写在了不该在的位置。比如 `<ul>` 里直接放文字不放 `<li>`，浏览器会把文字挪到列表外面。

## 样式没起作用

CSS 问题不属于这一组，但排查顺序这里先说一遍：

1. F12 里选中元素，看 Styles 面板里这条规则有没有被划掉——被划掉说明被别的规则覆盖了
2. 选择器写错，或者拼写错
3. `<link>` 的路径错了，样式文件根本没加载
4. 浏览器缓存了旧的 CSS（下一节讲）

## 改了代码页面没变化

八成是缓存。

开发的时候每次都按 `Ctrl + F5`（Mac 上是 `Cmd + Shift + R`）强制刷新。

不想老手动刷新，就打开 F12 的 Network 面板，勾上 "Disable cache"。

样式文件还可以在链接后面加个版本号，让浏览器认成新文件：

```html
<link rel="stylesheet" href="style.css?v=2">
```

每次改完把 `v=2` 往上加一位。

## 三个最容易犯的错

**把 `<p>` 嵌在 `<p>` 里**。段落不能嵌套，浏览器会把它们拆成并列的两个，结构跟你写的完全不一样。

**用 `<br>` 堆间距**。想隔开就用 CSS 的 margin，`<br>` 只用来做行内换行。

**用 `<div>` 配 `onclick` 当按钮**。看着能点，但键盘按 Tab 跳不过去、屏幕阅读器不知道它是什么、也拿不到回车键。要按钮就用 `<button>`。

## 一个排查顺口溜

先看 F12 里元素长什么样，再看控制台有没有红字，最后看 Network 里哪个文件 404。

这三步走完，HTML 层面的毛病基本都能定位到。
