## 问题根源
dpkg 仅负责解压、拷贝 deb 包内程序文件，不具备联网下载、自动补全依赖的功能。
Linux 桌面软件运行通常依赖系统底层库、字体、运行环境。本地 deb 安装时，如果系统缺少这些前置组件，dpkg 无法自行安装，会直接中断配置流程。
此时软件会停留在半安装、未配置完成状态。
## 典型报错特征
安装完成后终端出现关键字：  
leaving unconfigured
含义：文件已拷贝，但依赖缺失导致软件没有完成注册与配置，无法运行。
该状态会导致后续所有 apt 操作持续报错、无法正常安装或卸载软件。
## 标准修复逻辑
apt 可以读取 dpkg 的异常安装日志，自动识别当前系统缺失的依赖列表，并从官方软件源下载对应依赖、完成残余配置。
## 完整操作流程
```
sudo dpkg -i xxx.deb
sudo apt -f install
```
## 常见场景举例
• 微信 deb：缺失中文字体依赖
• 百度网盘 deb：缺失图形界面运行库依赖
以上场景无需手动查找依赖包，apt -f install 可全自动修复。
## 状态校验
```
sudo apt check
```
无输出即代表依赖全部修复，包管理器恢复正常。
无法修复的情况
如果执行 apt -f install 仍然报错：  
当前系统软件源中没有该 deb 所需版本的依赖包，通常是 deb 为 Ubuntu 专属版本，与 Debian 依赖库版本不兼容，无法自动适配。
