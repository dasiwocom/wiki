# CSS 总览

这一组共 14 篇，按顺序排好了：从"CSS 写在哪儿"开始，到"写了没反应怎么查"。

每一篇的末尾都有一行导航，打开第 1 篇一路点"下一步"就能顺着读完，随时点"路线图"回到这里。

这一组里的示例大部分是**真在页面上跑的**——写着框、按钮、表格的地方，都是渲染出来的效果，不是截图。鼠标放上去、拉一下窗口宽度，会有反应。

## 怎么用这组笔记

| 你现在是什么情况 | 怎么读 |
| --- | --- |
| 完全没写过 CSS | 从第一阶段开始顺着读。前三篇读完就能给页面换一套颜色和字体了 |
| 会一点，但布局总调不对 | 直接跳第 4 篇（盒子模型）和第 11 篇（flex），这两篇是绝大多数布局问题的根 |
| 想知道什么时候用 flex、什么时候用 grid | 看第 11 篇末尾和第 12 篇末尾的对照表 |
| 写了样式没反应 | 直接看第 14 篇，对着现象查 |

一个提醒：第 4 篇（盒子模型）看着枯燥，但它是最值钱的一篇。宽度算不对、padding 撑破了容器、两个块之间的空隙比预期大——全是这一篇的问题。

## 写 CSS 的几条习惯

这几条能省掉大量返工。

**开头先写几条全局重置**。默认的 margin、字体不一致，会让每个组件都要单独调一遍：

```css
*, *::before, *::after { box-sizing: border-box; }
body { margin: 0; font-family: system-ui, sans-serif; line-height: 1.7; }
img { max-width: 100%; height: auto; }
```

**只用类选择器**。别写 `#sidebar .list ul li a`，也尽量别用 id 写样式。选择器越简单，后面越好改。

**记住"这是内容还是样式"**。内容和结构归 HTML，外观归 CSS。写 HTML 时出现 `style="..."`，就该想想是不是该挪到 CSS 里。

**移动优先**。先写小屏能用的样式，再用 `min-width` 往上加。反过来写会越改越乱。

**每改一处就刷新看一眼**。CSS 不报错，写十行再一起看，出了问题不知道是哪行。

**实在想不通就用 `outline` 把所有盒子画出来**。看得见边界，问题基本就现形了。
