# 响应式，让页面适应各种屏幕

同一套代码，要能在大屏、笔记本、平板、手机上都不难看。这就是响应式。

## 先补上 viewport

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

没有这一行，手机会按 980px 宽的桌面页面渲染，然后整体缩小，字小到看不清。

有了它，CSS 里的 `width` 才等于手机的实际屏幕宽度，媒体查询也才会按真实宽度触发。

**响应式的第一步不是 CSS，是这一行。**

## 媒体查询

```css
@media (min-width: 768px) {
  .content {
    display: flex;
    gap: 24px;
  }
}
```

意思是"当视口宽度**达到** 768px 以上时，花括号里的样式才生效"。

在窄屏上这段完全不生效，页面就用默认的单列样式。

## min-width 还是 max-width

两种都能写，但方向建议统一成 `min-width`：

```css
/* 移动优先：先写小屏，再往大屏加 */
.card { display: block; }

@media (min-width: 768px) {
  .card { display: flex; }
}
```

```css
/* 桌面优先：先写大屏，再往小屏改（不推荐） */
.card { display: flex; }

@media (max-width: 767px) {
  .card { display: block; }
}
```

**移动优先**的好处：

- 手机用户最多，先用最基础的样式保证他们能用
- 小屏放宽很容易，反过来"把大屏布局塞进小屏"往往要塞一堆覆盖规则
- 用 `min-width` 的方向是"往上加"，不会互相覆盖

两个方向混着写，是响应式代码变成灾难的开始。

## 常用断点

断点按内容需要来定，但下面这几个是通行做法：

| 宽度 | 大概是 |
| --- | --- |
| `< 576px` | 手机竖直 |
| `≥ 576px` | 手机横屏、小平板 |
| `≥ 768px` | 平板 |
| `≥ 992px` | 笔记本 / 小桌面 |
| `≥ 1200px` | 桌面 |
| `≥ 1400px` | 大屏 |

写的时候只需要挑两三个，别每个都写。比如一个博客只要 768px 和 1200px 两个断点就够了。

## 媒体查询的其他条件

```css
@media (max-width: 767px) and (orientation: landscape) { }  /* 横屏手机 */
@media (min-width: 768px) and (max-width: 1199px) { }       /* 区间 */
@media (prefers-color-scheme: dark) { }                     /* 系统深色模式 */
@media (prefers-reduced-motion: reduce) { }                 /* 用户要求减少动画 */
@media print { }                                            /* 打印时 */
```

`prefers-color-scheme` 是现在做深色模式的标准做法：

```css
:root {
  --bg: #ffffff;
  --text: #2b2b2b;
}

@media (prefers-color-scheme: dark) {
  :root {
    --bg: #161618;
    --text: #ebebec;
  }
}
```

配合 CSS 变量（`var(--bg)`），整个站点换色只需要改这两处。

## 图片要跟着缩

```css
img {
  max-width: 100%;
  height: auto;
}
```

这两行几乎应该写进每个项目的 CSS 开头。

`max-width: 100%` 表示图片最宽不超过容器，`height: auto` 保证比例不变、不会被压扁。

想更省流量就用 `srcset`，让浏览器按屏幕挑合适的尺寸：

```html
<img src="pic-800.jpg"
     srcset="pic-400.jpg 400w, pic-800.jpg 800w, pic-1600.jpg 1600w"
     sizes="(max-width: 768px) 100vw, 800px"
     alt="示例图片">
```

浏览器会自己挑一张够用又不浪费的。图多的时候能省掉一大半流量。

## 不用媒体查询的两个技巧

**① grid 的 auto-fit**（见 [[12-grid 布局，做网格和卡片墙|上一篇]]）：

```css
grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
```

**② 用相对单位**。宽度用 `%`、`max-width`、`ch`、`rem`，字号用 `rem`，间距用 `em`，页面自己就会跟着缩放。

这两招能覆盖一半的响应式需求，剩下的才需要媒体查询。

## 一个媒体查询的现场演示

下面这个方块，窗口宽度小于 640px 时变成竖排、换个颜色；宽于 640px 才横排：

<style>
.wbd-mq {
  display: block;
  padding: 12px;
  border-radius: 8px;
  background: #c0392b;
  color: #fff;
  text-align: center;
}
@media (min-width: 640px) {
  .wbd-mq {
    display: flex;
    justify-content: space-between;
    background: #284b63;
  }
}
</style>

<div class="wbd-mq">
  <span>左边</span>
  <span>右边</span>
</div>

把浏览器窗口慢慢拉窄到 640px 以下，它会从蓝底横排变成红底竖排。

这段效果的全部代码：

```css
.box {
  display: block;
  background: #c0392b;
}
@media (min-width: 640px) {
  .box {
    display: flex;
    justify-content: space-between;
    background: #284b63;
  }
}
```
