# 样式不生效，先查这几种

CSS 最让人抓狂的一点是：**写错了不报错**。页面照常显示，只是没按你想的来。

所以排查得靠 F12，靠"现象 → 原因"，不能靠读代码。

## 第一步：打开 F12 的 Styles 面板

选中页面上的元素，右侧 Styles 面板会列出所有作用在它身上的规则。

看两种状态：

- **正常显示**：这条规则生效了
- **带删除线**：这条规则被别的规则覆盖了

带删除线的规则上面，会有一行告诉你"是谁覆盖了它"——直接点过去就能看到赢的那条。

**九成的 CSS 问题在这一步就能定位。**

## 常见原因一：被覆盖了

优先级更高的规则赢，顺序是：

```text
style 属性  >  id  >  类/属性/伪类  >  标签/伪元素
```

同权重时，后写的赢。

几个具体场景：

```css
/* 父级写死了，子级改不动 */
a { color: blue; }
.menu a { color: red; }   /* 这个赢，因为它更具体 */

/* 引入顺序反了 */
@import "reset.css";      /* 放在后面会把前面全盖掉 */
```

解决办法只有一个：**把选择器写到刚好够用，别用一长串去堆优先级**。靠 `!important` 打赢一次，后面就只能继续用 `!important`。

## 常见原因二：简写覆盖了具体属性

```css
.box {
  border-left: 4px solid red;
  border: 1px solid gray;   /* 这行把上一行整个重置了 */
}
```

`border`、`background`、`font`、`margin`、`flex` 这些简写属性会把没写到的部分重置成默认值。

顺序反过来（先 `border` 再 `border-left`）就没问题。

## 常见原因三：继承和"不继承"

有些属性会从父元素继承下来（`color`、`font-family`、`font-size`、`line-height`），有些不会（`border`、`padding`、`margin`、`background`、`width`）。

看不到效果的两种典型情况：

**① 你以为会自动继承，其实不会。**

给 `body` 设了 `border`，指望所有块都有边框——不会，`border` 不继承。

**② 你以为改一个就够了，其实被别处覆盖了。**

浏览器给 `<h1>`、`<p>`、`<ul>` 这些标签设了默认的 `font-size` 和 `margin`，所以给 `body` 设字号，标题的字号不会跟着变。

用 `inherit` 强制继承：

```css
input, button, textarea { font: inherit; }
```

表单控件默认不继承页面的字体，这一行能让它们跟页面统一。

## 常见原因四：选择器写错或拼不对

```css
.card { color: red; }     /* HTML 里 class 写的是 cards */
.btn { color: red; }      /* HTML 里写的是 class="button" */
.pargraph { }             /* 属性名拼错了 */
color: red;               /* 直接写在选择器外面了 */
```

还有个隐蔽的：**中文标点**。

```css
p { color: red； }     /* 中文分号 */
p ｛ color: red; }     /* 中文大括号 */
p { color： red; }     /* 中文冒号 */
```

这三种在编辑器里几乎看不出区别，但完全不生效。检查一下输入法。

## 常见原因五：文件根本没加载

F12 的 Network 面板刷新一下，看 `.css` 文件的状态码：

- `404`：路径写错了
- `200` 但内容是空的：文件内容有问题
- 文件压根没出现在列表里：`<link>` 标签写错了

检查 `<link>` 这几处：

```html
<link rel="stylesheet" href="style.css">
```

- `rel="stylesheet"` 有没有写对（写成 `stylesheets` 就废了）
- 路径相对的是 **HTML 文件**，不是 CSS 文件
- 文件名大小写在服务器上可能区分

## 常见原因六：缓存

改了 CSS，页面没反应，八成是浏览器还在用旧文件。

`Ctrl + F5`（Mac：`Cmd + Shift + R`）强制刷新。

开发时打开 F12 的 Network 面板，勾上 "Disable cache"，从此不用手动刷。

生产环境用版本号：

```html
<link rel="stylesheet" href="style.css?v=20261003">
```

## 常见原因七：元素压根没显示

样式没错，但元素本身不可见，你改什么都看不出来。

依次检查：

1. 自己或祖先有 `display: none`
2. 高度是 0（里面没有内容，又没设高度）
3. 被 `position: absolute` 挪到可视区外了
4. 颜色和背景一样
5. 被别的元素盖住了（`z-index`）

在 F12 里把鼠标悬停在 Elements 面板的节点上，页面上会给它高亮出一块区域。高亮不出来，说明它真的没有尺寸或者不在可见位置。

## 常见原因八：单位或者值写错了

```css
width: 100pxx;         /* 拼错，整条声明作废 */
width: 100;            /* 缺单位，无效（除了 0） */
line-height: 1.6px;    /* 本意是倍数，加了 px 就变成 1.6 像素 */
margin: 10 px;         /* 数值和单位中间有空格，无效 */
font-size: 16;         /* 缺单位 */
```

一条声明里只要有一个地方写错，**这一条就整条被忽略**，不是只忽略错的那个部分。

所以看到"某个属性没生效"，先把那一条完整地读一遍。

## 常见原因九：浏览器不支持

用了太新的属性，老浏览器直接跳过：

```css
gap: 10px;   /* 老版 Safari 的 flex 容器里不支持 */
```

在 [Can I use](https://caniuse.com/) 上查一个属性的兼容性，或者看 [MDN](https://developer.mozilla.org/zh-CN/docs/Web/CSS) 页面下方的浏览器支持表。

也可以直接问浏览器：

```css
@supports (display: grid) {
  .box { display: grid; }
}
```

`@supports` 里的样式只在浏览器支持某个属性时才生效，用来做渐进增强。

## 一个排查顺口溜

**先看 Styles 面板有没有删除线，再看 Network 有没有 404，最后逐字读一遍那条不生效的声明。**

这三步覆盖了绝大多数情况。
