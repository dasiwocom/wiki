# 表单验证，在服务端拦住错误

## 先记住一句话

**前端的验证是为了体验，服务端的验证才是为了安全。**

HTML 里的 `required`、`type="email"`，JavaScript 里写的那些检查，都能被人绕过——打开开发者工具改一下、或者用命令行直接发一个 POST 请求，表单根本不经过浏览器：

```bash
curl -X POST -d "email=乱写的" http://localhost:8000/register.php
```

所以：**凡是数据进了服务器，不管前端验证过没有，都要再查一遍。** 前端那套留着，因为能让用户少等一个来回。

## 验证些什么

按这个顺序，一层一层往下：

1. **有没有**：必填的字段存在吗、是不是空的
2. **格式对不对**：邮箱像邮箱吗、手机号是 11 位数字吗
3. **范围合不合理**：年龄是 -5 还是 200、长度有没有超
4. **业务规则**：这个用户名被人注册了吗、密码两次一致吗

前两层这一篇讲，后两层第 19 篇（查数据库）会遇上。

## 第一层：有没有

```php
<?php
$email = trim($_POST["email"] ?? "");

if ($email === "") {
    echo "邮箱不能为空";
}
```

**`trim()` 不能省。** 用户复制粘贴进来的内容经常带空格，不 trim 的话一个空格就能通过"非空"检查，而且存进数据库后和别的记录对不上。

判断"空"的时候，`empty()` 和 `=== ""` 的选择：

```php
<?php
$phone = $_POST["phone"] ?? "";

if (empty($phone)) { }      // 0 和 "0" 也算空 —— 手机号不会是 0，可以用
if ($phone === "") { }      // 严格只看空字符串

// 数字字段更稳妥的写法
$age = $_POST["age"] ?? "";
if ($age === "" || !is_numeric($age)) {
    // 没填，或者填的不是数字
}
```

`empty()` 会把 `"0"` 当成空，所以**数值字段（价格、数量、年龄）用 `empty` 判断"没填"是错的**——填 0 会被当成没填。

## 第二层：格式

### `filter_var`：现成的校验器

```php
<?php
$email = "abc@example.com";
var_dump(filter_var($email, FILTER_VALIDATE_EMAIL));   // string(16) "abc@example.com"

$bad = "abc@@example";
var_dump(filter_var($bad, FILTER_VALIDATE_EMAIL));     // bool(false)
```

**失败时返回 `false`，成功时返回原值。** 所以判断要写成：

```php
<?php
if (filter_var($email, FILTER_VALIDATE_EMAIL) === false) {
    echo "邮箱格式不对";
}
```

几个常用的：

```php
<?php
filter_var($url,   FILTER_VALIDATE_URL);    // 网址
filter_var($ip,    FILTER_VALIDATE_IP);     // IP 地址
filter_var($n,     FILTER_VALIDATE_INT);    // 整数
filter_var($n,     FILTER_VALIDATE_FLOAT);  // 小数
filter_var($b,     FILTER_VALIDATE_BOOLEAN);// "true"/"1"/"on" → true
```

整数还能限定范围：

```php
<?php
$age = filter_var($_POST["age"] ?? "", FILTER_VALIDATE_INT, [
    "options" => ["min_range" => 1, "max_range" => 120],
]);

if ($age === false) {
    echo "年龄必须在 1 到 120 之间";
}
```

这一句同时干了三件事：是不是整数、在不在范围内、转换成了 int 类型。

### 正则：格式有固定形状时

手机号、用户名、验证码这类"形状固定"的东西，用正则更直接。

```php
<?php
$phone = "13800138000";

if (!preg_match('/^1[3-9]\d{9}$/', $phone)) {
    echo "手机号格式不对";
}
```

这个正则读法：`^` 开头，`1`，`[3-9]` 第二位数是 3 到 9 之一，`\d{9}` 再跟 9 个数字，`$` 结尾。

**`^` 和 `$` 一定要写。** 不写的话，`abc13800138000xyz` 也会通过——正则只要求"里面能找到一段符合的"，而不是"整串都符合"。

几个常用的：

```php
<?php
// 用户名：3~16 位字母、数字、下划线
preg_match('/^[a-zA-Z0-9_]{3,16}$/', $username);

// 邮编
preg_match('/^\d{6}$/', $zipcode);

// 中文姓名：2~4 个汉字
preg_match('/^[\x{4e00}-\x{9fa5}]{2,4}$/u', $name);

// 密码：至少 8 位，且同时有字母和数字
preg_match('/^(?=.*[a-zA-Z])(?=.*\d).{8,}$/', $password);
```

最后一个用到"前瞻"，看着吓人，但可以直接抄来用，意思是"整个串里至少出现一个字母，至少出现一个数字，总长至少 8"。

`preg_match` 的返回值是 `1`（匹配到）、`0`（没匹配到）、`false`（正则本身写错了）。所以判断"不通过"要用 `!preg_match(...)`，它同时能接住 `0` 和 `false`。

**中文正则要加 `u` 修饰符**（在结尾那个 `/` 后面），告诉 PHP 按 UTF-8 处理，否则汉字匹配不上。

### `FILTER_SANITIZE_*` 不要用来做安全

```php
<?php
// 看起来像"清理"，其实是过滤，而且过滤得不干净
$email = filter_var($email, FILTER_SANITIZE_EMAIL);
```

它只是删掉某些字符，**不是一个可靠的防护手段**。防 XSS 靠输出时的 `htmlspecialchars`，防 SQL 注入靠预处理语句，各司其职。

## 收集所有错误，一次告诉你

一个一个报错，用户要来回提交五次。攒起来一次显示：

```php
<?php
$errors = [];

if ($email === "") {
    $errors["email"] = "邮箱不能为空";
} elseif (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
    $errors["email"] = "邮箱格式不正确";
}

if ($password === "") {
    $errors["password"] = "密码不能为空";
} elseif (mb_strlen($password) < 8) {
    $errors["password"] = "密码至少 8 位";
}
```

用**字段名当键**，这样在表单上能精确地把错误显示在对应输入框下面。

判断有没有错，用 `empty($errors)`；显示的时候遍历：

```php
<?php if (!empty($errors)): ?>
  <ul>
    <?php foreach ($errors as $msg): ?>
      <li><?php echo htmlspecialchars($msg); ?></li>
    <?php endforeach; ?>
  </ul>
<?php endif; ?>
```

也可以显示在字段旁边：

```html
<label>邮箱</label>
<input type="text" name="email" value="<?php echo htmlspecialchars($email); ?>">
<?php if (isset($errors["email"])): ?>
  <span class="err"><?php echo htmlspecialchars($errors["email"]); ?></span>
<?php endif; ?>
```

## 一个完整的注册表单

```php
<?php
$errors = [];
$data = ["username" => "", "email" => "", "password" => "", "password2" => ""];

if ($_SERVER["REQUEST_METHOD"] === "POST") {
    // ① 取值（统一 trim，避免后面到处补）
    foreach ($data as $k => $_) {
        $data[$k] = trim($_POST[$k] ?? "");
    }

    // ② 用户名
    if ($data["username"] === "") {
        $errors["username"] = "用户名不能为空";
    } elseif (!preg_match('/^[a-zA-Z0-9_]{3,16}$/', $data["username"])) {
        $errors["username"] = "用户名只能包含字母、数字和下划线，长度 3~16 位";
    }

    // ③ 邮箱
    if ($data["email"] === "") {
        $errors["email"] = "邮箱不能为空";
    } elseif (!filter_var($data["email"], FILTER_VALIDATE_EMAIL)) {
        $errors["email"] = "邮箱格式不正确";
    }

    // ④ 密码
    if (mb_strlen($data["password"]) < 8) {
        $errors["password"] = "密码至少 8 位";
    } elseif (!preg_match('/^(?=.*[a-zA-Z])(?=.*\d).+$/', $data["password"])) {
        $errors["password"] = "密码要同时包含字母和数字";
    }

    // ⑤ 两次输入是否一致
    if ($data["password"] !== $data["password2"]) {
        $errors["password2"] = "两次输入的密码不一致";
    }

    // ⑥ 全部通过才处理
    if (empty($errors)) {
        // 真实项目里：写进数据库
        $hash = password_hash($data["password"], PASSWORD_DEFAULT);

        echo "<p class='ok'>注册成功，用户名：" . htmlspecialchars($data["username"]) . "</p>";
    }
}
?>
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>注册</title>
</head>
<body>
<h1>注册</h1>

<?php if (!empty($errors)): ?>
  <ul class="errors">
    <?php foreach ($errors as $msg): ?>
      <li><?php echo htmlspecialchars($msg); ?></li>
    <?php endforeach; ?>
  </ul>
<?php endif; ?>

<form method="post">
  <p>
    用户名：<input type="text" name="username" value="<?php echo htmlspecialchars($data["username"]); ?>">
  </p>
  <p>
    邮箱：<input type="text" name="email" value="<?php echo htmlspecialchars($data["email"]); ?>">
  </p>
  <p>
    密码：<input type="password" name="password">
  </p>
  <p>
    再输一遍：<input type="password" name="password2">
  </p>
  <button type="submit">注册</button>
</form>
</body>
</html>
```

这个例子里有个小设计值得注意：**`$data` 一开始就有初始值**（全是空字符串）。这样"第一次打开页面"和"提交失败"两种情况，模板部分完全一样，不用写两套 `value`。

还有一个细节：**密码不参与回填**。用户填的内容里，密码框永远是空的——回填密码等于把它暴露在 HTML 源码里。

## 验证通过就安全了吗

不是。验证只保证"数据看起来合理"，后面还有两件事必须做：

- **输出到页面时**：`htmlspecialchars`（否则邮箱里带 `<script>` 也会执行）
- **写进数据库时**：预处理语句（否则姓名里带 `'; DROP TABLE users; --` 会出事）

三段分工明确：**验证 = 是不是我要的；转义 = 输出安不安全；预处理 = SQL 安不安全。** 少哪一段都会出事。
