# 运算符和类型比较，以及 == 和 === 的区别

## 算术运算

```php
<?php
var_dump(7 + 3);      // int(10)
var_dump(7 - 3);      // int(4)
var_dump(7 * 3);      // int(21)
var_dump(10 / 2);     // int(5)    —— 两个整数且除得尽，返回整数
var_dump(10 / 3);     // float(3.3333333333333)
var_dump(7 % 3);      // int(1)    —— 取余
var_dump(2 ** 10);    // int(1024) —— 乘方
```

除法这里有个容易忽略的点：**`10 / 2` 给的是整数 `5`，`10 / 3` 给的是浮点数。** 判断"除得尽"的时候不能靠类型去猜，要么用 `%`：

```php
<?php
if (10 % 2 === 0) {
    echo "是偶数";
}
```

`%` 只对整数有意义，浮点数要用 `fmod()`。

```php
<?php
var_dump(fmod(10.5, 3));    // float(1.5)
```

## 赋值运算的简写

```php
<?php
$n = 10;
$n += 5;      // 15   相当于 $n = $n + 5
$n -= 3;      // 12
$n *= 2;      // 24
$n /= 4;      // 6
$n %= 4;      // 2
$n **= 3;     // 8

$s = "你好";
$s .= "，小明";   // 字符串拼接的简写
echo $s;
```

```text
你好，小明
```

注意字符串拼接在 PHP 里是 **`.`（点）**，不是 `+`。在 JavaScript 里 `"a" + "b"` 是拼接，在 PHP 里 `"a" + "b"` 会尝试把两边变成数字再相加，结果是 `0`。

```php
<?php
var_dump("1" + "2");    // int(3)    不是 "12"
var_dump("1" . "2");    // string(2) "12"
```

写惯了前端代码的人最容易踩这个坑。

## 自增自减

```php
<?php
$i = 5;
echo $i++;    // 先输出 5，再加，$i 变成 6
echo $i;      // 6
echo ++$i;    // 先加，变成 7，再输出 7
```

写在变量前面叫前置，先加减再取值；写在后面叫后置，先取值再加减。**在 `for` 循环里 `$i++` 和 `++$i` 结果一样**，只有把它们塞进别的表达式里才有区别——那种时候建议拆成两行写，别人（和你自己）读起来才不费劲。

## 比较运算符

| 运算符 | 意思 | 例子 | 结果 |
| --- | --- | --- | --- |
| `==` | 松散相等（会转类型） | `1 == "1"` | `true` |
| `===` | 严格相等（类型也要一样） | `1 === "1"` | `false` |
| `!=` | 松散不等 | `1 != "1"` | `false` |
| `!==` | 严格不等 | `1 !== "1"` | `true` |
| `<>` | 同 `!=` | `1 <> 2` | `true` |
| `>` `<` `>=` `<=` | 大小 | `2 >= 2` | `true` |
| `<=>` | 比较后返回 -1 / 0 / 1 | `1 <=> 2` | `-1` |

最后的 `<=>`（叫太空船运算符）返回三档，专门给排序用：

```php
<?php
var_dump(1 <=> 2);    // int(-1)
var_dump(2 <=> 2);    // int(0)
var_dump(3 <=> 2);    // int(1)
```

## `==` 到底有多危险

`==` 在比较之前会先把两边转成同一种类型，转换规则不直观。

```php
<?php
var_dump(1 == "1");         // true
var_dump(1 == "1abc");      // false   （PHP 8）
var_dump(0 == "abc");       // false   （PHP 8；PHP 7 及更早是 true）
var_dump(0 == "");          // false   （PHP 8）
var_dump("1" == "01");      // true    —— 两个都是数字字符串，按数字比
var_dump("10" == "1e1");    // true    —— 都是数字字符串，按数字比
var_dump(100 == "1e2");     // true
var_dump(null == false);    // true
var_dump(null == 0);        // true
var_dump(null == "");       // true
var_dump([] == false);      // true
```

**"PHP 8 起"那几行是改过的行为。** PHP 8 之前，数字和非数字字符串比较时，字符串会被转成 `0`，于是 `0 == "abc"` 成立——这个规则害过很多人（最出名的一次是登录校验漏洞：某个 token 比较用了 `==`，结果任意字符串都能通过）。

**现在改成：数字和"无法解析成数字的字符串"比较时，把数字转成字符串，按字符串比。** 于是 `0 == "abc"` 变成 `false`。

不管版本新旧，结论都是同一个：**一律用 `===`。** 只有一个例外：

```php
<?php
// 想同时匹配 null 和 undefined 的变量时，用 ==，因为它等价于 isset($x) 的反面
if ($x == null) { }
```

其他场合，`==` 带来的便利远小于它带来的风险。

数组里也有同样的问题：

```php
<?php
$ids = [0, 1, 2];
var_dump(in_array("abc", $ids));          // false（PHP 8）；早版本是 true
var_dump(in_array("abc", $ids, true));    // 第三个参数 true = 严格比较
```

**`in_array` 和 `array_search` 永远传第三个参数 `true`。** 这是社区里公认的习惯，能省掉一整类难题。

## 逻辑运算

```php
<?php
$a = true;
$b = false;

var_dump($a && $b);     // false  与
var_dump($a || $b);     // true   或
var_dump(!$a);          // false  非
```

`&&`、`||` 是短路求值：`&&` 左边是假，右边根本不执行；`||` 左边是真，右边也不执行。这个特性经常被利用：

```php
<?php
// 先判断变量存在，再去用它的值，顺序不能换
if (isset($_GET["id"]) && $_GET["id"] > 0) { }
```

PHP 还有一套文字写法的逻辑运算符：`and`、`or`、`xor`、`not`。它们**优先级比 `=` 还低**，所以：

```php
<?php
$a = true and false;
var_dump($a);      // true —— 因为先算 $a = true，再算 and，结果被丢掉了

$a = (true and false);
var_dump($a);      // false
```

这就是"用 `and` 会出事"的典型。**一律用 `&&`、`||`**，那套文字写法只在某些老框架的特定位置才会见到。

## 三元的几种写法

```php
<?php
$age = 18;

// 完整三元
$label = $age >= 18 ? "成年" : "未成年";

// 短三元：条件为真时取自己的值，PHP 7.0 起支持
$name = "小明";
$display = $name ?: "匿名";        // $name 为真则用 $name，否则用 "匿名"
```

短三元 `?:` 判断的是**真假**，所以 `$name = "0"` 会走到"匿名"那一支，很多时候不是你想要的。

```php
<?php
// ?? ：左边存在且不为 null 就用左边，否则用右边
$page = $_GET["page"] ?? 1;

// ??= ：左边为 null 才赋值
$config["debug"] ??= false;
```

`??` 是接参数的标准写法，它**不会因为变量不存在而报错**——比 `isset(...) ? ... : ...` 短得多，效果一样。注意它只认 `null`，`0`、`""` 都算有值：

```php
<?php
$n = 0;
var_dump($n ?? 5);     // int(0)   不是 5
var_dump($n ?: 5);     // int(5)   —— 短三元把 0 当假
```

## 优先级：不确定就加括号

```php
<?php
var_dump(2 + 3 * 4);      // int(14)
var_dump((2 + 3) * 4);    // int(20)
```

`1 + 2 . "元"` 这类混着算的表达式，不同版本的语言结果可能不一样。**记不清优先级的地方一律加括号**，代码是给人看的，省那两个括号没有意义。
