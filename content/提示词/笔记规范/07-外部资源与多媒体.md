# 07 外部资源与多媒体

## 先说态度：手里的工具全都用上

写笔记的时候，**默认假设这些手段都能用，别保守**：

手绘 SVG · Mermaid 图表 · 内联 HTML · 图片 · 音频 · 视频 · 在线文档 · 幻灯片 · 代码块 · 表格 · Callout · 折叠块

真正要权衡的是**用得对不对**，不是**用得多不多**。

`02-排版与表达规范.md` 里说过"别把两行能说清的东西画成一大张 SVG"，那句话的意思是**表达效率低的时候别绕弯**，不是让你省着用。反过来同样成立：

- 讲到**结构、连线、位置、对比**——图比文字强，那就画，别用一整段话去描述一张图的形状
- 讲到**流程、分支、先后**——画流程图，别写"如果……那么……如果……那么……"
- 讲到**层级、分类、知识结构**——画思维导图
- 讲到**操作演示、实物、声音**——能找到视频音频就嵌进来，比写五百字有用
- 讲到**别人已经讲得很好的东西**——给链接，别自己复述

一句话：**能用图表说清的别用文字，能用现成资料的别自己造**。

## 讲解手段清单

| 手段 | 适合讲什么 | 要点 |
| --- | --- | --- |
| **手绘 SVG** | 元件符号、引脚排布、接线、物理结构、并排对比 | `viewBox` + `max-width:100%`；颜色用 CSS 变量适配亮暗主题。写法见 `03-语法清单.md` |
| **Mermaid** | 流程图、时序、状态机、**思维导图 `mindmap`**、甘特、类图 | 中文标签用引号包起来；前端渲染，RSS 里看不到 |
| **内联 HTML** | 折叠块 `<details>`、上下标、键盘按键 `<kbd>`、自定义布局 | 这个站点不过滤 HTML，写了就生效 |
| **图片** | 实物照片、软件截图、波形图 | `![[图.png]]` 嵌本地图，`![[图.png\|300]]` 改宽度；也可以用外链图片 |
| **音频** | 发音、音色、报警音、蜂鸣器、音乐 | `<audio controls src="地址">`，见下 |
| **视频** | 操作演示、实物运行、课程讲解 | `<iframe>` 嵌 B 站/YouTube 播放器，见下 |
| **在线文档 / 幻灯片** | 课件、PPT、表格、可交互内容 | 用 `<iframe>` 嵌在线版；本地 `.pptx` 网页播不了，要导出成图片或 PDF |
| **代码块** | 代码、命令、配置文件 | 标语言名，能高亮 |
| **表格 / 列表 / Callout** | 横向对比、要点罗列、补充提示 | 常规 Markdown 优先，见 `02-排版与表达规范.md` |

### 音频

```html
<audio controls src="https://example.com/sound.mp3" style="width:100%"></audio>
```

- 本地音频文件可以放在笔记同目录用相对路径引用，但**体积大、也不好维护**，优先用外链
- 一定要带 `controls`，否则读者看不到播放器

### 视频

```html
<iframe
  src="//player.bilibili.com/player.html?bvid=BV1xx411c7mD"
  style="width:100%;aspect-ratio:16/9;border:0;border-radius:8px"
  allowfullscreen>
</iframe>
```

- B 站要把 `https://www.bilibili.com/video/BV...` 换成 `//player.bilibili.com/player.html?bvid=BV...`
- YouTube 用 `https://www.youtube.com/embed/视频ID`
- 必须给宽度和 `aspect-ratio`，否则会缩成默认的小尺寸

### 幻灯片、课件这类在线内容

本地的 `.pptx` / `.key` 在网页上放不出来，三条路：

1. **导出成图片**放进库里，用 `![[图.png]]` 嵌（最稳）
2. **用在线文档的 iframe**：腾讯文档、Google Slides、微软 Office Online 都支持嵌入，把分享链接换成嵌入地址
3. **转成 PDF** 后给外链下载

## 不要闭门造车：笔记要跟外部世界连着

笔记不是模型记忆的转储。**只靠自己脑子里那点东西写出来的笔记，容易过时、容易错、也容易窄。**

三个具体的理由：

- **读者需要出处和延伸阅读**。一个说法从哪来的？想深入该看什么？外链就是答案
- **模型的记忆会过时**。版本号、参数、API 名字、价格、硬件型号，这些隔一段时间就变，凭记忆写就是埋雷
- **别人讲得更好的，就别自己讲一遍**。第三方教程有图有例子的，给个链接加一两句概括，比复述一遍有用得多

### 什么时候给外链

| 情况 | 怎么做 |
| --- | --- |
| 讲某个语言/框架的语法 | 给该主题的权威教程站链接（如编程类给菜鸟教程、MDN、官方文档） |
| 提到某个芯片、元件、软件 | 给数据手册、官方下载页 |
| 某个操作有现成视频演示 | 嵌播放器，或者给视频链接 |
| 引用了别人的观点、数据、图片 | 标注来源，别装成自己写的 |
| 这篇笔记只是某个大主题的一小块 | 给"继续往下学该看什么"的入口 |

### 去哪找

- **编程/语法类**：菜鸟教程（runoob）、MDN、W3School、官方语言文档
- **硬件/芯片**：厂商数据手册（datasheet）、官方参考手册
- **软件工具**：官方帮助文档、GitHub 仓库的 README
- **视频讲解**：B 站、YouTube（优先选播放量高、年份近的）
- **问答/踩坑**：Stack Overflow、官方论坛、GitHub Issues

**写技术类笔记时，动手之前先查一遍**，尤其是这几类会变的东西：版本号、命令参数、API 名称、配置项、价格、型号规格。查到什么就按什么写，别凭印象。

### 外链怎么写

- **写清楚这是什么**，不要只甩一个裸网址：

  > ❌ "参考资料：https://www.runoob.com/markdown/md-tutorial.html"
  >
  > ✅ "Markdown 语法的完整清单可以看[菜鸟教程的 Markdown 教程](https://www.runoob.com/markdown/md-tutorial.html)，里面每个语法都有在线试写的例子。"

- **放在相关的位置**，别堆在结尾当"参考资料"区。讲表格的地方链表格教程，讲换行的地方链换行说明
- 结尾仍然**不要**堆"推荐阅读"——外链是顺着内容给的，不是凑格式的（见 `01-内容规范.md`）

### 引用，不是搬运

第三方资料**给链接 + 一两句概括**就够了。整段整节搬过来，既啰嗦又有版权问题。

图片、视频如果来自别人，注明来源。自己截图、自己画的图不用。
