# 05 系列笔记规范

**只有在一个主题确实需要拆成多篇时才用这份规范。** 单篇能讲透的就写成一篇，别为拆而拆——判断标准见 `01-内容规范.md` 的第一节。

## 什么时候该拆

拆的信号：

- 一个主题涵盖**好几类完全不同的用法**，每类都要展开讲（比如 Markdown 语法：换行、表格、代码、图表，彼此独立）
- 单篇会长到**一屏屏往下滚**，读者很难定位自己要的那一段
- 有明确的**学习先后**，硬塞进一篇会打乱顺序

不拆的信号：

- 拆完每篇只剩三五句话，靠双链才能读懂 → 那是把一篇切碎了，拼回去
- 几篇之间要反复互相引用才能讲明白 → 说明它们本来是一个整体

## 拆完之后必须有"顺序"

这是最容易漏的一步。**多篇笔记堆在一个目录里，如果没有明确顺序，读者（尤其是新手）根本不知道从哪篇开始看。**

文件列表的默认排序是按文件名，跟学习顺序毫无关系。所以顺序必须由**内容**给出，而不是指望读者自己猜。

四件事缺一不可：

1. 有一篇**路线图页**（索引页）
2. 每篇末尾有**位置导航**（第几篇、上一步、下一步、回到路线图）
3. 路线图里写清**每篇学完能做什么**，而不是只列个链接
4. **文件名带上序号前缀**，让侧边栏也按顺序排

## 文件名加序号前缀

顺序不能只写在内容里——**侧边栏（文件列表）是按文件名排序的**（字典序，跟磁盘顺序、跟学习顺序都无关）。不加序号的话，侧边栏里 13 篇是乱的，读者从侧边栏点进去就会跳到中间某一篇。

所以系列笔记的文件名统一加两位序号：

```text
01-换行到底怎么回事，回车、两空格、空行有什么区别.md
02-标题怎么用，分级、锚点和页内跳转.md
03-文字强调：粗体、斜体、删除线、高亮和上下标.md
...
```

- 用**两位**（`01` 而不是 `1`），`10` 以后的排序才不会错
- 路线图页**不加序号**，它是入口，不参与编号
- 序号后面直接接原标题，不用加空格或连字符之外的花活

代价是网址里会带上序号。想要旧网址不失效，就在 frontmatter 的 `aliases` 里写上原来的文件名（`alias-redirects` 会自动做跳转）——但这个字段由站主自己填。

链接的显示文字用 `|短名` 收一下，不然导航行会被长标题撑爆：

```md
[[03-文字强调：粗体、斜体、删除线、高亮和上下标|文字强调]]
```

这样页面上显示的是"文字强调"，点进去还是那篇。路线图的篇目表同样这么处理。

## 路线图页怎么写

路线图页是这个系列的入口，独立于编号之外（它是第 0 篇，不参与"第 N / 共 M 篇"）。

要有这几块：

**开头说明这是按顺序排的**，并说明导航在哪、怎么用：

> 这一组共 13 篇，是**按顺序排好的**。每一篇的末尾都有一行导航，所以你只要打开第 1 篇，一路点"下一步"就能顺着读完，随时点"路线图"回到这里看全局。

**"你现在是什么情况 → 怎么读"的对照表**，让不同起点的读者都能立刻找到入口：

| 你现在是什么情况 | 怎么读 |
| --- | --- |
| 完全没写过 Markdown | 从第一阶段第 1 篇开始，按顺序读 |
| 某个具体语法不会写 | 直接在下面表格里找 |
| 照着网上教程写却没效果 | 直接看第 13 篇 |

**按阶段分组的篇目表**，每组给一个标题和一个目标。表格至少三列：第几篇 / 篇名 / 学完你能做什么。

- 阶段一般 3~4 个就够，别切得太碎
- 每阶段的标题要写清这一阶段的目标，比如"第一阶段：先把一篇笔记写成型"
- **每篇的"学完你能做什么"要写具体的收获**（"知道回车、两空格、空行分别产生什么结果"），不要写"介绍换行语法"这种目录式的话

**阶段之间可以插一句提醒**，比如读完第一阶段建议拿自己真实的笔记练一遍——这类话能让路线图活起来，不是冷冰冰的索引。

## 顺序怎么排

按**学习顺序**排，不是按重要程度、也不是按字母：

1. **先高频后低频**：日常 90% 时间会用到的排在最前面
2. **先基础后依赖**：被别的篇依赖的排前面（比如先讲标题，再讲"链到某一节"）
3. **由浅入深**：同一类语法里，简单的在前、花哨的在后
4. **排查类放最后**："写了没反应怎么办"这种是出问题时才查的，不要放前面吓退新手
5. **"需要时才学"的单独成一组**：画流程图、写公式这类，明确告诉读者可以跳过，用到再回来

典型的四段式：

| 阶段 | 放什么 |
| --- | --- |
| 第一阶段 | 学完就能写出完整东西的最小集合 |
| 第二阶段 | 让它更好读、能互相关联 |
| 第三阶段 | 用得上才学的进阶能力 |
| 第四阶段 | 出问题时的排查 |

## 每篇末尾的导航行

**放在文章最后**（正文写完、和正文之间空一行加一条 `---` 分隔线），一行引用：

```md
---

> 系列第 3 / 13 篇 · ← 上一步：[[02-标题怎么用，分级、锚点和页内跳转|标题怎么用]] · 下一步：[[04-列表怎么写，嵌套、任务列表和列表里塞内容|列表怎么写]] → · 路线图：[[Markdown 语法总览]]
```

- **不要放在文章开头**。读者刚点进来，第一眼应该是内容，不是"这是第几篇"；开头堆一行导航等于每篇都先给读者看一眼目录。
- 第一篇没有"上一步"，最后一篇没有"下一步"，不用硬凑
- **每篇都要有"路线图"链接**，这样从任何一篇点进来都能回到全局
- 就用一行引用，别做成导航卡片

## 系列里的每一篇，仍然是独立文章

顺序是给"顺着读"的人用的，**不代表每篇可以依赖别的篇**。

- 每篇照样要能单独打开读懂（例子自足、背景交代完整），因为很多人是从搜索结果直接点进第 7 篇的
- 每篇的标题照样按"现象 + 要解决的事"来起，系列内风格一致即可，不要变成"第 7 讲：表格"
- 每篇照样不要套同一个结尾

## 自查

- [ ] 有一篇路线图页，并且它不参与编号？
- [ ] 路线图里写清了"学完能做什么"，而不是只列链接？
- [ ] 分了阶段，每阶段有目标，而不是 13 篇平铺一个表？
- [ ] 每篇末尾都有"第 N / 共 M 篇 + 上一步/下一步 + 路线图"，而开头是干净的正文？
- [ ] 顺序是按学习先后排的，不是按文件名排序？
- [ ] 随便抽一篇单独打开，能读懂吗？
