# 换行到底怎么回事，回车、两空格、空行有什么区别

在 Markdown 里写东西，最容易让人怀疑人生的一件事就是：**我明明按了回车，它为什么不换行？**

或者反过来——在 Obsidian 里看着好好的分行，发布到网站上全粘成一坨。

这不是你记错了语法，是 Markdown 里"换行"这件事本身就分**三种不同的结果**，而它们看起来又很像。这篇把这件事从头理清楚。

## 三种写法，三种结果

先记住这张图，后面所有内容都是在展开它：

| 你在源码里做了什么 | 页面上得到什么 | 视觉特征 |
| --- | --- | --- |
| 直接按一次回车 | 取决于一个开关，可能换行也可能合并 | 换行了的话，两行**贴得很紧** |
| 行尾敲两个空格再回车 | 一定换行 | 两行**贴得很紧** |
| 空一行再写 | 一定分段 | 两行之间有**明显的空隙** |

最后那一列是关键：**"换行"和"分段"是两件不同的事**，它们的视觉效果不一样。

很多人以为自己要的是"换行"，其实想要的是"分段"；也有人反过来。下面分开讲。

## 分段：空一行

空一行是 Markdown 里最没歧义的操作。它的意思是：**这一段到此结束，下面是新的一段。**

```md
这是第一段。

这是第二段。
```

渲染出来是两段文字，中间有一段空白。

那段空白不是你敲出来的，是**浏览器给的**——每个段落（HTML 里的 `<p>` 标签）默认带有上下间距。所以你会看到：

- 段落和段落之间：<span style="color:var(--tertiary)">有明显空隙</span>
- 段落内部的行与行之间：只有普通的行距，没有额外空隙

这就是为什么你会感觉"有时候有间隔有时候没有"。**有间隔的是分段，没间隔的是段内换行。**它们是两个不同的东西，不是 Markdown 时灵时不灵。

## 换行：只断行，不分段

有时候你想在**同一段之内**断开，比如写地址、写诗、写歌词：

```md
北京市海淀区
中关村大街 1 号
100080
```

想要的效果是三行紧挨着，中间不要有段落那种大空隙。

要做到这个，有两种写法。

**写法一：行尾敲两个空格**

```md
第一行  
第二行
```

（注意第一行末尾那两个空格，它们看不见，但必须敲。）

**写法二：写 `<br>` 标签**

```md
第一行<br>
第二行
```

两种效果完全一样。前者是 Markdown 的原生语法，后者是 HTML，都行。

`<br>` 的好处是**看得见**，不容易漏；坏处是写多了源码会显得乱。两个空格的好处是干净，坏处是你根本看不出自己敲没敲——这也是它最让人抓狂的地方。

## "硬换行"到底是个什么词

这个词听着玄，其实就一句话的事：

> **硬换行 = 源码里按一次回车，页面上就真的换一行。**

它的反面叫**软换行**：你按回车只是为了让源码看着整齐（比如一行太长，折一下），渲染时**不算数**，两行会被拼回一行。

再往深一层说，"硬换行"这个名字来自 HTML：

- 换行在 HTML 里就是 `<br>` 这个标签，它的全称是 **br**eak
- 所以"把回车变成 `<br>`"就叫硬换行（hard line break）
- 不变成 `<br>`、只是把两行拼起来的，叫软换行（soft line break）

**Markdown 的两种流派就是在这里分道扬镳的：**

| 流派 | 单回车怎么处理 | 谁是这样 |
| --- | --- | --- |
| 软换行派（传统） | 拼回一行，要换行得敲两个空格 | 原始 Markdown 规范、CommonMark、GitHub |
| 硬换行派（现代） | 直接换行 | Obsidian 默认、Notion、微信/知乎编辑器 |

两边都有道理。传统派说：源码换行是为了排版源码，不该影响内容；现代派说：我按了回车就是要换行，你凭什么不给我换。

**所以这不是"对的写法"，是"你用的那个工具选择了哪一边"。**

## 三个环境的对照

具体到你的笔记库，涉及三个环境，它们的默认设置**是不一样的**：

| 环境 | 只按一次回车会怎样 | 由什么决定 |
| --- | --- | --- |
| Obsidian（默认） | **换行** | 设置里的 Strict line breaks，默认关闭，也就是默认硬换行 |
| 标准 Markdown / GitHub | **合并** | 规范本身就是这么定的 |
| 本站（当前配置） | **换行** | `quartz.config.yaml` 里的 `hard-line-breaks` 插件，已设为 `enabled: true` |

看出问题了吗：**Obsidian 默认是硬换行，Quartz 默认是软换行。**如果你两边都不去动，就会出现最让人困惑的现象——

> 我在 Obsidian 里看着是分行的一段话，发布到网站上变成了一大坨。

### 本站是怎么开成硬换行的

Quartz 有个专门的插件管这件事，在配置文件里长这样：

```yaml
- source: "@quartz-community/hard-line-breaks"
  enabled: true      # 改成 false 就回到标准行为
  order: 90
```

它内部用的是 `remark-breaks` 这个通用插件，原理极其简单：**把源码里每一个换行符都替换成一个 `<br>`**。没有别的逻辑。

想关掉就把它改回 `false`，改完重新构建即可。

> [!warning] 这个插件只影响网页
> Obsidian 不读这个文件。你在 Obsidian 编辑器里看到什么，跟它一点关系都没有。所以两边要一致，得各自设置。

### Obsidian 那边怎么改

设置 → 编辑器 → **Strict line breaks**（中文界面可能叫"严格换行"）。

- **不勾**（默认）：硬换行，回车即换行
- **勾上**：软换行，遵循标准 Markdown，回车会合并，要换行得敲两个空格

本站现在开着硬换行，所以 Obsidian 保持默认不勾，两边就一致了。

### 怎么确认自己站上现在是哪一种

不用猜，写个最小的测试：

```md
aaa
bbb
```

构建完看网页源码（F12 或右键"查看源代码"）：

- 看到 `aaa<br>bbb` → 硬换行，开着
- 看到 `aaa bbb` 或者同一个 `<p>` 里两行文字 → 软换行

## 开了硬换行之后，写法要变

这是最实际的一件事。硬换行开着的时候，你的源码排版习惯决定了最终效果。

**推荐的写法：一行一句话。**

```md
这是第一句。
这是第二句，跟上一句在同一段里，但另起一行。
这是第三句。
```

上面这三行在页面上会显示成紧贴的三行——因为它们中间没有空行，属于同一段。

**想分段就空一行：**

```md
这是第一段，讲一件事。

这是第二段，讲另一件事。
```

这样两句话之间会有明显空隙，读者一眼能看出话题换了。

### 一个要小心的地方

开了硬换行之后，**千万别为了源码好看把一句话折成两行**：

```md
这是一句很长的话，写到一半发现太长了
于是我按了个回车继续写。
```

上面这样写，页面上会真的断成两行，看起来就像两句。如果你本来只是想让源码每行短一点，那就别回车——让编辑器自动折行显示就好（Obsidian 里叫"软折行"）。

一句话总结这个习惯：**源码里的回车 = 你想让读者看到的换行。不想让读者换行，就别回车。**

## 什么时候该用哪个

具体到场景，可以这样选：

| 你想写什么 | 用什么 | 为什么 |
| --- | --- | --- |
| 普通正文，想换话题 | 空一行分段 | 有空隙，读者知道话题变了 |
| 地址、诗歌、歌词 | 直接回车（硬换行） | 要的就是一行行紧挨着 |
| 英文段落，一行一句 | 直接回车 | 源码好读，页面也分行 |
| 并列的好几条 | 列表 `-` | 有项目符号，语义更清楚 |
| 代码、命令行输出 | 代码块 | 等宽字体，不会丢空格 |
| 表格的单元格里要换行 | `<br>` | 见下面 |

### 关于"英文文章不能换行，只好用列表"

这是个很常见的误解，值得单独说。

以前本站是软换行的时候，写英文（或者任何逐行内容）会遇到：源码里一行一句，发布后全糊成一段。于是很多人退而求其次用列表：

```md
- 第一行
- 第二行
```

这样确实能分行——**但代价是多了一堆项目符号**，而这些内容根本不是"并列项"，用列表在语义上是错的。

现在本站开了硬换行，这个土办法就不需要了：直接回车就行，干净、语义也对。

列表该用在它该用的地方：**确实是并列的几条**。关于列表的完整写法见 [[列表怎么写，嵌套、任务列表和列表里塞内容]]。

## 表格里的换行是个例外

有一处地方，硬换行和两空格**都不管用**：表格的单元格里。

表格的一行就是一行，你在源码里怎么写都不会让它变成两行。要换行只能写 `<br>`：

```md
| 项目 | 说明 |
| --- | --- |
| 地址 | 北京市海淀区<br>中关村大街 1 号 |
```

这是为数不多的、`<br>` 不可替代的场景。表格的其它细节见 [[表格怎么写，对齐和单元格里的特殊内容]]。

## 换行和其它语法的配合

几个容易含糊的地方，实测结论都在这：

- **引用块里**：回车会换行。写 `> 第一行` 回车 `> 第二行`，出来是两行紧挨着的。
- **列表项里**：想在一个列表项里写两段，把第二段缩进到和文字对齐，中间空一行（缩进的那个空格不会被当成代码块）。
- **代码块里**：**不受硬换行影响**，代码里该几行就是几行，不会被插入多余的 `<br>`。
- **脚注里**：同样遵循正文的换行规则。
- **标题里**：标题不能换行，一个标题就是一行。

## 常见坑

**敲了两个空格但没生效**

先确认这个站现在是软换行还是硬换行——如果是硬换行开着，其实你根本不需要两个空格。如果你是照着别的教程学的，那份教程大概率讲的是 GitHub 的行为。

**想要分段却只按了回车**

结果是一堆句子紧贴在一起，看起来像一大段。解决办法就是空一行。

**反过来，想要紧贴却空了行**

结果每段之间都有空隙。想让几行紧挨着，就别空行。

**在表格里死活换不了行**

表格单元格只认 `<br>`，见上面那一节。

**改了配置没生效**

Quartz 的配置改完要**重新构建**才会反映到网页上。运行：

```bash
npx quartz build
```

**两边看起来不一样**

多半是 Obsidian 和本站的开关不一致。对照"三个环境的对照"那一节，两边调成一样。
