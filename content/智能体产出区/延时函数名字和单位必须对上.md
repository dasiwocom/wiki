# 延时函数名字和单位必须对上

## 一句话

延时函数的**名字、参数、时间单位**三者必须一起对上。只改名字不改参数，函数实际延时不变；名字和调用对不上，则根本编译不过。

## 两类错误，表现完全不同

### 错误一：名字对不上 → 编译报错

```c
void Delay500us()   // 定义的是这个
...
Delay500ms();       // 调用的却是这个
```

编译器会报这一串：

| 报错 | 含义 |
| --- | --- |
| `C206: 'Delay500ms': missing function-prototype` | 调用之前没见过这个函数 |
| `L1: UNRESOLVED EXTERNAL SYMBOL` | 链接时到处找，找不到它的实现 |
| `L2: REFERENCE MADE TO UNRESOLVED EXTERNAL` | 某一处调用指不到东西 |
| `L16: UNCALLED SEGMENT` | 你定义了某个函数，但没人调用它（死代码） |

> [!warning] L1 / L2 不能无视
> 这只是"警告"级别，但烧进去程序会跑飞，现象就是灯完全不按预期动作。编译结果必须是 **0 Error、0 Warning** 才算过。

### 错误二：单位差 1000 倍 → 能编译，但看不出效果

```c
void Delay500ms()
{
    // 里面其实是 1 毫秒的参数
}
```

- `500us` = 0.5 毫秒
- `500ms` = 500 毫秒

**差 1000 倍。** 用 500 微秒去闪灯，一秒闪 1000 次，人眼根本分辨不了，看起来就是「常亮，但亮度偏暗」，不像闪烁。

> [!tip] 人眼能分辨的闪烁大约到每秒 50 次
> 想看见明显的闪烁，单次亮或灭的时间至少要在 **50 毫秒**以上。

## 为什么改了名字函数不会变慢

软件生成的延时函数，时长全靠里面那几个循环变量的初值决定：

```c
unsigned char i, j;
i = 2; j = 239;        // 这组参数算出来约 1000us = 1 毫秒
do { while (--j); } while (--i);
```

**函数名只是个标签，改名字不会改变任何执行时间。** 想改成 500 毫秒，必须换配套的参数（通常是多一层循环、多一个变量 `k`）。

## 最省事的改法

用烧录软件自带的**软件延时计算器**：选好晶振频率 → 填定时长度 → 生成 → 整段粘到 `main` 前面。生成的函数名、参数、注释里的频率三者是配套的，粘完直接编译就能过。

> [!note] 频率要和板子一致
> 计算器里填的频率必须和板载晶振一致才准（常见 12MHz 或 11.0592MHz）。差 8% 肉眼看不出来，但做精确时序时要留意。

## 自己写也行：拿 1 毫秒重复若干次

```c
void Delay1ms()
{
    unsigned char i, j;
    i = 2; j = 239;
    do { while (--j); } while (--i);
}

void Delay500ms()
{
    unsigned int i;
    for(i = 0; i < 500; i++) Delay1ms();
}
```
