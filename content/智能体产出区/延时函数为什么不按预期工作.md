# 延时函数为什么不按预期工作

## 一句话

延时函数的**名字、循环参数、时间单位**三者必须一起对上。只改名字不改参数，函数实际延时一点没变；名字和调用对不上，则根本编译不过。

## 软件延时到底是怎么"等"的

51 单片机没有操作系统，也没法真的"睡"一会儿。所谓延时，就是**让 CPU 原地空转一堆无意义的循环**，转够了就相当于过去了那么多时间。

所以软件生成的延时函数长这样：

```c
void Delay1ms()      // @12.000MHz
{
    unsigned char i, j;
    i = 2;
    j = 239;
    do
    {
        while (--j);
    } while (--i);
}
```

里面的 `2` 和 `239` 不是随便写的，是软件按晶振频率**算出来的循环次数**：转这么多圈，刚好耗掉 1 毫秒。

**由此得出两条关键结论：**

1. **函数名只是个标签。** 把 `Delay1ms` 改成 `Delay500ms`，里面的 `2` 和 `239` 一个字没变，它就还是 1 毫秒。改名字不会让函数变慢。
2. **换晶振，时长就变。** 12MHz 下算出来的参数，放到 11.0592MHz 的板上，时间会差约 8%。

## 错误一：名字对不上 → 编译都过不了

```c
void Delay500us()   // 定义的是这个
...
Delay500ms();       // 调用的却是这个
```

编译器会甩出一串：

| 报错 | 含义 |
| --- | --- |
| `C206: 'Delay500ms': missing function-prototype` | 调用到它之前，没见过这个函数 |
| `L1: UNRESOLVED EXTERNAL SYMBOL` | 链接时到处找，找不到它的实现 |
| `L2: REFERENCE MADE TO UNRESOLVED EXTERNAL` | 某一处调用指不到东西（会带地址） |
| `L16: UNCALLED SEGMENT` | 你定义了某个函数，但没人调用它（死代码） |

前三条是同一个问题的连锁反应，`L16` 则是反过来提醒你"那个 `Delay500us` 白写了"。

> [!warning] L1 / L2 不能当没看见
> 它们只是"警告"级别，不阻止生成 hex，但烧进去程序会**跑飞**——CPU 跳到一个没有指令的地址，现象就是灯完全乱来。编译结果必须是 **0 Error、0 Warning** 才算过。

## 错误二：单位差 1000 倍 → 能编译，但看不出效果

```c
void Delay500ms()
{
    // 里面其实是 1 毫秒的参数
}
```

- `500us` = 0.5 毫秒
- `500ms` = 500 毫秒

**差 1000 倍。** 用 0.5 毫秒去闪灯，一秒闪 1000 次。人眼大概只能分辨到每秒 50 次以下的闪烁，再快就靠"视觉暂留"糊成一片，看起来是**常亮、亮度偏暗**，根本不叫闪烁。

> [!tip] 想看见闪烁，单次亮/灭至少 50 毫秒
> 这是人眼的生理限制，跟代码无关。做呼吸灯、流水灯时按这个下限来设计时间。

## 正确的两种写法

**写法一：用软件自带的延时计算器（推荐）**

烧录软件（STC-ISP）里有「软件延时计算器」：填晶振频率 → 填定时长度（选**毫秒**还是微秒要看清）→ 生成 → 整段粘到 `main` 前面。

生成的函数名、循环参数、注释里的频率三者是配套的，粘完直接编译就能过。500 毫秒的生成结果会多一层循环、多一个变量 `k`，因为单层循环撑不到那么久：

```c
void Delay500ms()		//@12.000MHz
{
	unsigned char i, j, k;

	_nop_();
	i = 4;
	j = 205;
	k = 187;
	do
	{
		do
		{
			while (--k);
		} while (--j);
	} while (--i);
}
```

`_nop_()` 是补一个机器周期用来凑整的，配合 `#include <INTRINS.H>` 使用，别删。

**写法二：拿 1 毫秒重复若干次**

```c
void Delay1ms()
{
    unsigned char i, j;
    i = 2; j = 239;
    do { while (--j); } while (--i);
}

void Delay500ms()
{
    unsigned int i;
    for(i = 0; i < 500; i++) Delay1ms();
}
```

两种误差都在几毫秒以内，肉眼分不出来。

## 时间不准？先查晶振

延时计算器里填的频率**必须和板载晶振一致**才准。常见的是 12MHz 和 11.0592MHz 两种。

板载晶振是芯片旁边那个银白色的小金属壳元件，上面印着频率数字。如果填 12MHz 而板子实际是 11.0592MHz，实测时间会慢约 8%——闪烁实验无所谓，做串口波特率、精确时序时就会出错。

> [!note] 为什么会有 11.0592 这种怪频率
> 因为它能被精确整除出常用的串口波特率（9600、19200…）。12MHz 算出来有误差。做串口通信的板子常用它。
