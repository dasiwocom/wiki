## 现象

在移动设备上，点击输入框唤起键盘时，整个页面会突然放大并抖动。或者，输入框获得焦点时视口会滚动、乱跳。点击页面其他地方后布局就恢复正常了。

## 原理

### 自动缩放的根因：字号小于 16px

这是 **iOS Safari 和部分 Android 浏览器**的硬性规则：

> 当 `<input>` / `<textarea>` 元素的计算字号低于 16px 时，触发 `focus` 会让浏览器自动放大页面。

原因：在小屏手机上，浏览器厂商要保证用户输入时的文字可读。Safari 通过强制放大来实现聚焦时 16px 的最小可读字号，失焦后恢复缩放。

这就造成了一个众所周知的前端坑：设计师为了美观把输入框字号设成 14px / 15px，结果在移动端触发了非受控的浏览器缩放和布局位移。

Android Chrome 也有类似行为。实现细节不同，但小于 16px 的输入框同样容易出现非预期的缩放。

### 页面跳动的根因：聚焦时自动滚动

获得焦点后，浏览器会自动把该输入框滚动进视口，尤其是当它在屏幕外或者被虚拟键盘遮住的时候。再叠上键盘弹出和页面上正在跑的动画，这种原生滚动行为就会产生刺眼的视觉跳动。

## 解决方案

### 方案 1：输入框字号 ≥ 16px（主修法）

```css
input, textarea {
    font-size: 16px;   /* iOS 在 >=16px 时不会触发强制缩放 */
}
```

这是唯一的根本解法。用 viewport meta 禁用缩放只治症状。把字号设对才是治根因。

> 重要提示：用 `transform: scale()` 把一个 16px 的输入框视觉上缩到 14px 是**不管用的**。iOS 按最终渲染出来的视觉尺寸判断，自动缩放照样会触发。

### 方案 2：抑制聚焦时的自动滚动

想避免视口跳动时用这个：

```javascript
input.focus({ preventScroll: true });  // 聚焦元素但不滚动页面
```

### 方案 3：等动画结束再聚焦

如果你的输入框在一个滑出/展开的 UI 组件里（比如下拉搜索面板）。在过渡还在跑的时候调用 focus，浏览器的滚动会和你的动画打架，结果是卡顿。

```javascript
// 等面板过渡（例：300ms）结束之后再激活 focus
setTimeout(() => input.focus({ preventScroll: true }), 320);
```

## 小结

- 移动端输入框聚焦时的非预期缩放，源自 **iOS 对字号 < 16px 的输入框的强制缩放规则**。
- 主要修法：给输入框设 `font-size: 16px` 或更大。
- 布局跳动：用 `focus({ preventScroll: true })` 跳过自动滚动。在带动画的容器里时，延迟到动画结束再聚焦。
- 这是移动端浏览器的标准行为，跟你的标记是哪个框架生成的无关。
