# 移动端侧边抽屉卡顿/响应慢：四层排查链

## 现象

移动 Web 应用里的全屏侧边抽屉（滑入菜单）在三个不同方面让人难受：

1. **首次点击卡顿** —— 抽屉最后会出来，但「点了打开」这个动作明显慢/滞涩。
2. **滑动动画掉帧** —— 动起来不顺，在微信内置浏览器（X5/XWeb）或低端机上尤其明显。
3. **响应有延迟感** —— 从点按钮到抽屉开始移动之间有一段可感知的空档。

每个症状的根因都不一样。按这个顺序修。

## 第 1 层：首次点击卡顿 → 渲染工作跑在 click 处理函数里

### 原因

菜单内容是**首次点击时才懒渲染**的：`marked.parse()` + `DOMPurify.sanitize()` + 给每个链接绑 click 处理函数，全部同步跑在按钮的 `click` 处理函数里。动画要等这些全部跑完才开始，所以第一次点击会阻塞几十毫秒（慢设备上更多）。

### 修法

在页面加载时就把内容预渲染一次（抽屉此时在屏幕外/已平移出去，渲染过程看不见），click 处理函数只负责切一个 CSS class：

```js
// 页面初始化时：
drawerContent.innerHTML = DOMPurify.sanitize(marked.parse(MENU_MD, { gfm: true }));
// ...绑定链接处理函数...
// click 处理函数里：只做 classList.toggle('open')
```

## 第 2 层：动画掉帧 → backdrop-filter 每帧重算

### 原因

顶部导航栏用了 `backdrop-filter: blur(30px)`（毛玻璃）。当一个全屏抽屉在它下面滑动时，被模糊区域的内容每帧都在变，逼着浏览器每帧重跑一次昂贵的模糊滤镜。再叠上走 CPU（非 GPU）的 transform 动画，结果就是移动端 WebView 里明显的掉帧。

### 修法

两部分：

1. 强制抽屉走 GPU 合成：

```css
#drawer {
    transform: translate3d(-100%, 0, 0);
    will-change: transform;
    transition: transform .2s ease-out;
}
#drawer.open { transform: translate3d(0, 0, 0); }
```

2. 抽屉打开期间临时关掉导航栏的模糊（关闭时恢复）：

```css
#nav.no-blur, #nav.no-blur > * {
    -webkit-backdrop-filter: none !important;
    backdrop-filter: none !important;
}
```

```js
function setDrawer(open) {
    drawer.classList.toggle('open', open);
    nav.classList.toggle('no-blur', open);
}
```

## 第 3 层：响应延迟 → 移动端 300ms 点击延迟

### 原因

移动端浏览器（iOS Safari、Android Chrome，尤其是微信的 X5/XWeb WebView）历来会把 `click` 事件推迟约 300ms，用来判断这次点击是不是双击（比如双击缩放）。为了可访问性把 viewport meta 里的 `user-scalable=no` 去掉之后，这个延迟就回来了 —— 按钮看起来就慢了 300ms，读起来就是「卡」。

### 修法

一行 CSS 就能告诉浏览器这个元素不需要双击检测：

```css
.vp-icon-btn { touch-action: manipulation; }
```

不需要任何 JavaScript。（**不要**依赖 `user-scalable=no` —— iOS Safari 10+ 本来就会忽略它，而且禁用缩放损害可访问性。）

## 第 4 层：动画时长

0.3s 的 ease-in-out 曲线在移动端感觉拖沓；`0.2s ease-out`（起步快、迅速收住）才显得干脆。这个是小头，但和上面几项叠在一起就很明显。

## 小结：「抽屉感觉卡」的排查清单

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 首次点击卡顿 | 渲染工作跑在 click 处理函数里 | 页面加载时预渲染 |
| 动画掉帧 | backdrop-filter 重算 + CPU transform | `translate3d` + `will-change` + 动画期间关掉模糊 |
| 响应延迟 | 移动端 300ms 点击延迟 | `touch-action: manipulation` |
| 整体感觉慢 | 动画曲线太长 | `0.2s ease-out` |
