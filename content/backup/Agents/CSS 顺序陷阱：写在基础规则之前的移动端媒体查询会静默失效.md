# CSS 顺序很重要：写在基础规则之前的移动端媒体查询会静默失效

## 现象

两个页面（前台和后台管理）共用一套「一模一样」的顶部导航栏——CSS 是一行一行从其中一个文件复制到另一个的。桌面端两个页面像素级一致。但在 DevTools 的移动视口（≤768px）下布局不一样：前台的 `#vp-nav-left` 宽 **306px**，后台的只有 **282px**，正好窄了 24px。

两边的 `#vp-nav-right` 都是 72px，所以 flex 容器宽度相同。差的 24px 正好是 `12px × 2`，也就是移动端的内边距：一个页面在移动端生效了 `padding:0 12px`，另一个还在用桌面端的 `padding:0 24px`。

## 原理

CSS 层叠规则：**两条规则优先级相同时，写在后面的赢。**

```css
/* admin.css —— 媒体查询写在前面（文件开头） */
@media (max-width:768px) {
    #vp-nav { padding:0 12px; }   /* 优先级: 0,1,0 */
}
/* ...同一文件后面... */
#vp-nav { padding:0 24px; }        /* 优先级: 0,1,0 —— 相同，但写在后面 → 赢 */
```

关键陷阱：**媒体查询不会提升优先级。** `@media` 只决定规则「什么时候生效」，块里面选择器的优先级和基础规则完全一样。所以：

- 媒体规则写在基础规则**之后** → 小屏上移动端内边距生效 ✓
- 媒体规则写在基础规则**之前** → 基础规则**连小屏上也是它赢** ✗（而且是静默失效，不报错）

前台文件里媒体查询在第 912 行、基础规则在第 606 行（媒体在后 → 正确）；后台文件里媒体查询在第 20 行、基础规则在第 73 行（媒体在前 → 坏了）。复制规则的**内容**不够，它们的**顺序**不一样。

## 如何复现

```css
/* 坏：媒体查询在基础规则之前 */
#vp-nav { padding:0 12px; }          /* 本意是移动端 */
...
#vp-nav { padding:0 24px; }          /* 桌面端 —— 把上面的全覆盖了 */

/* 好：媒体查询在基础规则之后 */
#vp-nav { padding:0 24px; }
...
@media (max-width:768px) {
    #vp-nav { padding:0 12px; }
}
```

## 解决方案

- **让媒体查询始终排在它所修改的基础规则之后**——这也是最好读的顺序（先基础样式，后响应式调整）。
- 如果挪不动位置，就提高优先级或用 `!important`，但优先用顺序而不是 `!important`。
- 在文件之间「复制」CSS 时，要核对**顺序**，不能只看有没有这条规则。快速检查法：对两条规则分别 `grep -n`，比较行号——响应式那条必须在基础那条之后。

## 破案的调试手法

不要整页对比——在 DevTools 里**一次只比一个计算出来的尺寸**：

1. 在两个页面上选中同一个元素（`#vp-nav-left`）。
2. 对比 `getComputedStyle` / 盒模型的数值：宽度 306 vs 282 → 缩小到 24px 的差异。
3. `vp-nav-right` 两边都是 72px → flex 容器一致 → 差异一定在导航栏**内部**：它的 padding。
4. `24px = 12px × 2` → 直接指向那条没生效的移动端内边距规则。

## 小结

- 媒体查询不增加优先级——同优先级的规则由**声明顺序**决定，写在基础规则之前的移动端规则是静默死亡的。
- 跨文件复制 CSS 时，**顺序也要一起复制**，只复制内容不够。
- 用计算值对比（一次一个维度）来二分定位布局差异，别靠肉眼看。
