## 现象

在移动设备上，点击按钮、链接或文件列表项会触发一瞬间的颜色闪烁（一层半透明的灰色遮罩），手指抬起后立刻消失。用鼠标在桌面电脑上点击则**不会**出现这个效果。

## 根因

这是移动端浏览器内置的点击反馈功能。

在桌面上，你有丰富的交互反馈：鼠标悬停时的 `hover` 状态、点击时的 `active` 状态。移动端触摸屏没有 `hover` 的概念。浏览器需要某种方式告诉用户「这次点击被接收到了」。

为此，浏览器的做法是：**在你手指按下的瞬间渲染一层半透明的灰色遮罩**，手指抬起后它就消失。

这种原生行为的缺点：

- 灰色高亮由浏览器控制，你没法自定义它的颜色、透明度或时长。
- 它经常和你的站点设计系统打架。
- 快速点击时，遮罩会一闪而过，就成了用户感知到的刺眼闪烁。

简而言之：**浏览器注入了一个你不想要的默认样式。**

## 解决方案

用一行 CSS 关掉它：

```css
* {
    -webkit-tap-highlight-color: transparent;
}
```

`transparent` 会让浏览器跳过那层灰色点击高亮。

建议把这三条一起加上，顺手修掉移动端浏览器另外几个讨厌的默认值：

```css
* {
    -webkit-tap-highlight-color: transparent;
    -webkit-touch-callout: none;   /* 禁用长按系统菜单（复制/搜索等） */
    outline: none;                  /* 去掉点击时的蓝色焦点环 */
}
```

## 补充要点

- 这个机制适用于 WebKit 系浏览器（Chrome、Safari、微信内置浏览器）。`-webkit-` 前缀是必需的。
- 关掉高亮之后，点击就完全无声了。如果你想要点击反馈，就自己实现 CSS 状态（比如给 `active` 状态一个轻微的颜色变化）。视觉和时机就完全归你控制了。
- 这是移动端 Web 开发三条必备的 reset 规则，建议所有面向移动端的项目都加上。

## 排查日志（参考）

一开始怀疑是 CSS 的 `hover` / `active` 过渡。把所有过渡删掉修好了桌面端行为，但移动端的闪烁依旧。然后又怀疑焦点环，给按钮加了 `outline: none`，还是没改善。最后才定位到这个**只在移动端存在**的 `tap-highlight` 机制，用一条 `-webkit-tap-highlight-color: transparent` 解决。**排查时一定要先区分「只在桌面出现」还是「只在移动出现」**，能省下大量时间。
