## 现象

在一个静态工具站（ToolBox，Apple 风格设计）上，切换明暗模式在桌面端很顺，但在手机上感觉「卡得要命」。背景和工具卡片几乎瞬间切换，而卡片标题（`JSON Formatter`）等元素上的**文字颜色**、以及顶部栏里的小 SVG 却明显滞后。把过渡时长从 0.3s 缩到 0.18s、再缩到 0.05s，错位变小了但始终没消失；只有当过渡设为 `0s`（帧内瞬时替换）时，背景和文字才落在同一帧上。

## 原理

### 为什么第一版用的是全局动画过渡

最初的目标是**「不闪」**，于是沿用了早前笔记里那套 VitePress 式的兜底规则：

```css
*, *::before, *::after {
    transition: background-color .3s ease, color .3s ease, border-color .3s ease;
}
```

在桌面端这很完美：每个元素用同样的时长和缓动函数做动画，谁都不会跳脱同步。这条规则一直没被质疑过，因为桌面端的演示效果很好。

### 为什么在移动端动画永远无法*完全*同步

即便每个元素声明了完全相同的 `transition-duration`，同一帧里仍然跑着两类不同的工作：

- `background-color` 可以由**合成器 / GPU** 插值完成。
- `color`（文字字形）必须在**主线程上重新光栅化**，这是 CPU 密集的。

在一台繁忙的低端手机上，文字重绘的帧被排在背景的帧之后，所以不管时长压到多短，文字在视觉上都会落后背景一两帧。0.05s（约 3 帧）能缩小差距，但消不掉。

雪上加霜的是，`*` 这条兜底规则让**成千上万个节点同时做动画**，而吸顶头部的 `backdrop-filter: blur(20px)` 在换色期间每帧都要重新模糊图层 —— 在手机上是很大的 GPU 开销，把「卡」从微妙变成了显著。

### 约束变了，解法也该变

- 最初的约束：**消除闪烁** → 需要动画过渡。
- 最终的约束：**消除可感知的延迟 + 文字/背景绝对同步，且要在弱鸡移动 GPU 上做到** → 此时过渡本身成了障碍。

结论：`0s` 的「瞬时快照」在一个渲染帧内换掉所有颜色。因为没有东西需要调度，文字和背景必然同时落地，昂贵的每帧开销也随之消失。这是「统一过渡」这一族里最极端的形式，也是唯一**在架构上**同步的形式。

## 解决方案

### 方案 1（最初）：全局统一过渡，0.3s → 0.18s → 0.05s

沿用既有的无闪烁范式。桌面端没问题；手机上一直有「文字拖尾」的感觉。用 `--theme-dur` 作为单一旋钮（CSS 变量），这样只需改一个值。可接受的代价：缩短时长只是创可贴，不是根治。

### 方案 2（中间态）：剥掉昂贵的动画属性

```css
*, *::before, *::after {
    transition: background-color var(--theme-dur) var(--ease),
                color var(--theme-dur) var(--ease),
                border-color var(--theme-dur) var(--ease);
}
```

- 从全局过渡里去掉了 `box-shadow`（每帧动画很贵；hover 阴影只存在于 `(min-width: 641px) and (hover: hover) and (pointer: fine)` 规则里，所以触屏设备根本不会碰它）。
- 在手机/窄屏上禁用 `backdrop-filter`：

```css
@media (max-width: 640px) {
    :root { --theme-dur: 0.08s; }
    .site-header { backdrop-filter: none; -webkit-backdrop-filter: none; }
}
```

这让切换快了很多，但在真机上文字依然拖尾。

**注意：** headless Chromium 里的 `(pointer: coarse)` 模拟并不能可靠地匹配真实触摸输入；之所以额外加 `max-width: 640px` 兜底，正是因为它是确定性的。别用指针模拟来做「仅移动端」行为的决策。

### 方案 3（最终）：瞬时切换，`--theme-dur: 0s`

```css
:root { --theme-dur: 0s; }
```

包括文字在内的所有颜色在同一帧内变化 —— 没有调度，没有卡顿的中间帧。需要保持顺滑的交互动画，在同一元素上用单独的时长列出来即可：`transform` / `opacity` 用各自的时长，而颜色用 `var(--theme-dur)`（现在是 `0s`），比如卡片 hover 抬起仍然做 0.2s 动画，而它的颜色是瞬变的。

取舍：你会失去桌面高分屏上用户可能期待的柔和淡入/插值。当「帧内同步」和移动端性能优先于精致感时，接受这个取舍。

## 小结

- 最初的修法针对的是**闪烁**（需要动画）；最终的需求是**弱机上的帧内同步**（动画成了敌人）。重新调数值之前，先回头看目标。
- 文字 `color` 动画相对 `background-color` 是受限的（QoS 不同），所以相同的时长在低端 CPU 上仍然会失同步。唯一无懈可击的同步是 `0s` 切换。
- 整页换色的移动端优先规则：保持瞬时、去掉 `backdrop-filter`、把 `box-shadow` 从动画里剔除；动画只留给廉价的、用作交互反馈的属性（`transform`、`opacity`）。
- 当兜底的 `*` 规则和某个具体元素打架时，用一份**完整的 transition 列表**去覆盖它（这个属性是整体替换，不是合并）—— 绝不要用 `transition: none !important`。
