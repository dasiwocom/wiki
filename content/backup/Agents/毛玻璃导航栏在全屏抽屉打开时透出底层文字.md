# 毛玻璃导航栏在全屏抽屉打开时透出底层文字

## 现象

站点顶部有个毛玻璃导航栏（`background: transparent` + `backdrop-filter: blur(30px)`）—— 盖在普通页面内容上效果很好。但当一个全屏侧边抽屉（或任何浮层）滑进来时，导航栏区域会透出**底层页面的文字**。背景浅的时候抽屉看着脏；后面内容一多，文字透过玻璃清晰可读，看起来就是坏了。

更糟的是：浮层关闭时导航栏会恢复原样 —— 但在打开/关闭的动画期间，有一瞬间底层文字是可见的，也就是闪一下。

## 原理

毛玻璃本质上就是两样东西：

1. `background: transparent` —— 元素**自己不画任何东西**，所以它背后的一切都透过来。
2. `backdrop-filter: blur(...)` —— 浏览器把它背后的内容模糊掉，这只是**弱化**了透出，并没有消除它。文字还是可见的，只是变虚了。

这在普通内容之上是个特性（页面在半透明条下面滚动）—— 但当**浮层打开**时就变成了 bug：导航栏下面的区域现在被抽屉盖住了，可导航栏自己仍然显示它背后的东西（正好待在那儿的页面内容）。眼睛读到的是「文字从 UI 外壳里渗出来」，而不是「好看的玻璃」。

## 偷偷附送的第二个 bug：过渡让它闪

朴素的修法是浮层打开时把导航栏变成实色：

```css
#nav.overlay-open { background: var(--bg); }
```

但站点通常有全局过渡规则：

```css
*, *::before, *::after {
    transition: background-color .25s ease, color .25s ease, border-color .25s ease;
}
```

于是背景变化**在 0.25s 内渐变**。浮层动画（0.2–0.3s）和背景过渡在赛跑：打开的最初几帧，导航栏还是半透明的，底层文字就闪了一下。然后才稳定成实色。结果就是「打开时会闪一下」。

## 解决方案

### 1. 浮层打开期间把导航栏改成实色

```css
#nav.overlay-open,
#nav.overlay-open > * {
    background: var(--bg) !important;
    -webkit-backdrop-filter: none !important;
    backdrop-filter: none !important;
}
```

由 JS 在抽屉打开时加上（关闭时移除）。

### 2. 在打开状态下**关掉背景过渡**

不这么做的话，实色背景是淡入的，动画期间文字照样会闪：

```css
#nav.overlay-open,
#nav.overlay-open > * {
    transition: background-color 0s !important;
}
```

这条过渡规则只在浮层打开期间生效，所以抽屉关闭后正常的玻璃效果（以及平滑过渡回去）不受影响。

### 3. 附赠：这还顺手修好了掉帧

`backdrop-filter` 很贵。全屏抽屉在导航栏下面滑动时，浏览器每帧都要重算模糊。在浮层动画期间禁掉 `backdrop-filter`，就把这份开销整个去掉了 —— 抽屉动画在移动端 WebView 上明显更顺。（参见抽屉卡顿那篇相关笔记。）

## 小结

- 毛玻璃（`transparent` + `backdrop-filter`）**永远**会透出底层内容 —— 这是它的本性；只有在普通页面内容之上才可接受。
- 浮层/抽屉打开时，在这段时间内把导航栏切成实色背景，并且**在该状态下关掉背景过渡**，否则最初几帧会闪出透出的文字。
- 浮层期间关掉 `backdrop-filter` 还能去掉每帧的模糊重算 → 动画更顺。
- 检查清单：浮层打开 → 导航栏实色 + 无过渡 + 无模糊；浮层关闭 → 恢复玻璃。
