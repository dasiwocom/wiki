# 00 总纲：这套规范怎么用

这是给 AI 用的**笔记写作规范**，拆成了 7 个文件，放在同一个目录里。

| 文件 | 管什么 | 什么时候用 |
| --- | --- | --- |
| `00-总纲.md` | 怎么用这套规范、三条硬规则、核心判断标准 | **每次都要带上** |
| `01-内容规范.md` | 写什么、写多细、用什么视角、怎么开头结尾 | 每次都要带上 |
| `02-排版与表达规范.md` | 排版松紧、形式要不要换、语法的优先级 | 每次都要带上 |
| `03-语法清单.md` | 这个库支持哪些语法、哪些不生效、SVG 怎么画 | 需要写代码/画图/用到特殊语法时 |
| `04-文件与元数据规范.md` | frontmatter 怎么填、文件名怎么起、放哪个目录 | 每次都要带上 |
| `05-系列笔记规范.md` | 一个主题拆成多篇时怎么排序、怎么导航 | 只有写系列时才带 |
| `06-写完自查.md` | 写完逐条核对 | 写完自己查用 |
| `07-外部资源与多媒体.md` | 图表/视频/音频/幻灯片怎么用，以及怎么引外部资料 | 讲实操内容、技术类笔记时要带 |

用法：把**总纲 + 需要的那几份**一起复制给 AI。日常写单篇笔记，`00 + 01 + 02 + 04` 就够了；要写系列就再加 `05`，讲操作或技术内容就再加 `07`。

## 先说怎么读这套规范

下面写的都是**默认倾向，不是铁律**。每一条都没有绝对的意思，按大意执行就好，不要逐字死抠。

- 遇到"这条在这里反而不合适"的情况，**以写出来的效果好为准，偏离就是了**，不用请示，也不用为了满足清单而硬凑。
- 真正硬的只有三类：
  1. **技术事实**（哪些语法开、哪些关，文件名哪些字符不能用）
  2. **frontmatter 的字段约定**
  3. **视角**：笔记是给陌生人看的，不能留下"这是替人代写"的痕迹
- 判断标准始终是那一个：**零基础的陌生人单独打开这一篇，能不能读懂、能不能用**。

## 一句话目标

写笔记的目标只有一个：**让人看完真的学会**，不是把信息搬过来。

## 四条最容易被违反的

如果时间只够记几条，记这四条：

1. **往详细里写**，别压缩成几句结论。概括是给复习用的，详细才是给学习用的。
2. **形式要换着用**。别一路散文到底，该列表格的地方列表格，该配图的地方配图（反过来，也别把两行能说清的东西画成一大张 SVG）。
3. **视角站读者那边**。别出现"你给我的图""用户提供的资料""本文由 AI 生成"这类话，也别用"本站"这种只有站主自己懂的说法——对读者来说就是"这个站点"。
4. **工具大胆用，别闭门造车**。SVG、Mermaid、HTML、图片、音频、视频、在线幻灯片，能用的都用上；写技术笔记要引外部资料（教程站、官方文档、数据手册、视频），别只靠模型自己的记忆——记忆会过时，而且别人讲得更好的地方不用自己复述一遍。

第 4 条容易矫枉过正，两个方向的错都要避免：**不敢用**（什么都不画、什么外链都不给）和**乱用**（把简单东西复杂化、整段搬别人的内容）。详见 `07-外部资源与多媒体.md`。
