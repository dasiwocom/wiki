# 06 写完自查

这是给写笔记的人（AI）自己用的**检查项**，写完逐条过一遍。**不要把它搬到笔记正文里当结尾**——那是凑格式，见 `01-内容规范.md`。

## 内容

- [ ] 零基础的人单独打开这一篇，能读懂吗？
- [ ] 够详细吗？有没有哪一步、哪个结论是"一句话带过但其实要展开"的？
- [ ] 讲清楚"为什么"了吗，还是只有操作步骤？
- [ ] 有没有"这类板子""那个软件""前面说的"这类默认读者有背景的指代？

## 视角

- [ ] 有没有"你给我的图""用户提供的资料"这类暴露代写关系的说法？
- [ ] 有没有"本站"这种站主视角的词？该说"这个站点"
- [ ] 文件名是读者搜得到的现象描述，还是站内的内部叫法？

## 形式

- [ ] 有没有一整屏没断句的长段？
- [ ] 形式够多样吗？有没有连续好几屏都是纯文字、该列表格的地方在写段落、该配图的地方在干讲？
- [ ] 常规 Markdown 是不是用够了？有没有本来表格两行就说清、却画了一大张 SVG 的地方？
- [ ] 反过来：讲到元件、引脚、接线、结构这类东西的地方，配图了吗？
- [ ] 有没有"明明画张图就说清，却写了一整段"的地方？
- [ ] 视频、音频、在线文档、幻灯片这类手段，能用上的用了吗？（见 `07-外部资源与多媒体.md`）

## 外部资源

- [ ] 技术内容有没有给外部出处（教程站、官方文档、数据手册）？还是全靠模型记忆？
- [ ] 会变的信息（版本号、参数、型号、价格、API 名）查过了吗？
- [ ] 外链是不是写了"这个链接里有什么"，而不是甩一个裸网址？
- [ ] 有没有把别人的内容整段搬过来？给链接 + 一两句概括就够了
- [ ] 用了别人的图或视频，注明来源了吗？

## 元数据

- [ ] frontmatter 是不是只有 `description` 有值、其余三个留空？
- [ ] 有没有多加字段？
- [ ] 文件名避开了 `?` `:` 这类非法字符？

## 结构

- [ ] 结尾有没有硬塞的"推荐阅读""小结""排查清单"？
- [ ] 如果是系列：每篇有"第 N / 共 M 篇 + 上一步/下一步 + 路线图"吗？路线图里写了"学完能做什么"吗？
