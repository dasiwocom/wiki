# 网上抄来的 Markdown 写法不生效，先查这几种

> 系列第 13 / 13 篇 · ← 上一步：[[12-Markdown 做不到的，直接写 HTML|直接写 HTML]] · 路线图：[[Markdown 语法总览]]

Markdown 有很多"方言"。网上教程讲的是 GitHub、Typora、某个博客平台还是 Obsidian，往往不说清楚，照抄过来发现没效果，又不知道是自己写错了还是环境不支持。

这篇记录的是**在这个站点上实测过、确认不生效**的写法。每一项都写了实际现象和替代方案，省得你再试一遍。

## 不支持的清单

| 写法 | 实际会发生什么 | 用什么替代 |
| --- | --- | --- |
| `:smile:` 表情短代码 | 原样显示成一串字符 | 直接粘贴 emoji 字符 😀 |
| 定义列表（`术语` 换行后 `: 定义`） | 变成普通的几行文字 | 表格或列表 |
| 正文里写 `#标签` | 当成普通文字，不会变成可点的标签 | 写在 frontmatter 的 `tags` 里 |
| `^2^` `~2~` 上下标 | 原样显示，且 `^` 容易被当成块 ID | `<sup>` / `<sub>` 标签 |
| `![[xxx.html]]` 嵌入 HTML 文件 | 什么都不显示 | 把 HTML 直接写在正文里 |
| `![[xxx.mp4]]` 嵌入视频 | 什么都不显示 | `<iframe>` 嵌站外播放器 |
| Dataview 查询块 | 只有本机 Obsidian 里能看到，网页上不生效 | 手动维护列表，或者避开 |

下面挑几个容易踩的展开说。

## 表情短代码

很多平台支持 `:smile:`、`+1`、`:tada:` 这种写法，输入短代码自动变成表情。

这个站点不支持。实测结果是：`:smile:` 会被当成**行内代码**显示出来，读者看到的是一串带底色的字符，而不是笑脸。

**替代办法很直接：把 emoji 字符本身粘进去。**😀 🎉 ✅

从哪复制？系统自带的emoji面板（Windows 按 `Win + .`，macOS 按 `Ctrl + Cmd + 空格`），或者去网上找 emoji 表。

## 定义列表

有些 Markdown 方言支持这种写法：

```md
术语
: 这是术语的解释
```

这个站点不支持，实测会变成两行普通文字——`术语` 是一段，`: 这是术语的解释` 是另一段，冒号还在。

**替代方案：**

- 解释很短 → 用列表：`- **术语**：解释`
- 要解释好几个术语 → 用表格，两列分别是术语和解释
- 术语很多、解释很长 → 用标题分段，见 [[02-标题怎么用，分级、锚点和页内跳转|标题怎么用]]

## 正文里的标签

在正文里写 `#教程`，很多平台会把它变成可点的标签。

这个站点实测：**不会生成标签链接**，它就只是普通文字，前面带个井号。

原因也简单：这个站点的标签来自 frontmatter 里的 `tags` 字段，不扫描正文。

**所以要分类就写在属性区里**，见 [[10-Frontmatter 属性区和标签|Frontmatter 属性区]]。

顺便说一句：正文里写 `#` 开头的文字还有个风险——如果它后面跟着的是空格加文字，某些渲染器会把它当成**标题**。所以不打算用标签功能的话，连写都别写。

## 上下标的方言写法

`^2^` 和 `~2~` 是部分 wiki 系统的写法，这个站点不支持。实测行为：

- `^2^` 原样显示。更麻烦的是，`^` 在 Obsidian 里是**块 ID**的标记符号，写在一行末尾会被当成块编号，可能在别处产生莫名其妙的链接
- `~2~` 原样显示，而且容易和删除线 `~~` 打架

**用 HTML 标签**，这是哪儿都通用的：

```md
X<sup>2</sup>、H<sub>2</sub>O
```

## 嵌入 HTML 文件和视频

这个站点的配置里有一项：

```yaml
- source: "@quartz-community/obsidian-flavored-markdown"
  enabled: true
  options:
    enableInHtmlEmbed: false
```

`enableInHtmlEmbed: false` 的意思就是：**不许把 HTML 文件嵌入进来**。所以 `![[xxx.html]]` 写了没反应。

**替代：直接把 HTML 写在笔记正文里。**这个站点不过滤 HTML 标签，写进去就能生效，包括 `<svg>`、`<iframe>`、`<details>` 这些。见 [[12-Markdown 做不到的，直接写 HTML|直接写 HTML]]。

视频同理。别用 `![[演示.mp4]]`——这个站点不支持嵌入本地视频。要么用 `<iframe>` 嵌 B 站播放器，要么放个外链地址。

## Dataview

Dataview 是 Obsidian 的**插件**，不是 Markdown 语法。它的查询块长这样：

````md
```dataview
LIST FROM #教程
```
````

在 Obsidian 里它能自动列出所有带某标签的笔记。但网页上没有这个插件，**查询不会执行**，读者看到的要么是一堆源码，要么是空白。

**替代：手动维护一个列表**，或者用标签页（这个站点会自动生成每个标签的汇总页）。

同样的道理适用于所有 Obsidian 插件语法——Templater、Excalidraw、各种 Advanced 插件的语法，网页上都不生效。

## 为什么会有这些差异

一句话：**Markdown 没有唯一的强制标准。**

2004 年的原始规范很简陋，后来各家各自扩展：

- GitHub 搞了 GFM（表格、任务列表、删除线）
- Obsidian 加了双链、Callout、高亮
- 各种 wiki 系统加了上下标、定义列表
- 后来有了 CommonMark 想统一，但只统一了基础部分

这个站点的做法是：**Obsidian 的方言 + GitHub 的风格，两套都开**，再叠一层 Quartz 自己的插件。所以上面那些"别的系统的方言"不生效，是正常现象。

## 怎么自己验证一个写法

与其猜，不如试。步骤：

1. 建一个临时笔记，只写那一小段要测的语法
2. 构建到临时目录：

```bash
npx quartz build -o 临时目录名
```

3. 用文本编辑器打开输出的 HTML，搜你写的那段文字，看它被包在了什么标签里
4. 测完把临时笔记删掉

比如你想知道 `==高亮==` 生不生效，就去输出里搜"高亮"，看它是不是被 `<span class="text-highlight">` 包着。

这个方法对所有语法都适用，比翻教程快。
