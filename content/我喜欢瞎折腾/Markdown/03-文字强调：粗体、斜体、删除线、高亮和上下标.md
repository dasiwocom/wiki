# 文字强调：粗体、斜体、删除线、高亮和上下标

> 系列第 3 / 13 篇 · ← 上一步：[[02-标题怎么用，分级、锚点和页内跳转|标题怎么用]] · 下一步：[[04-列表怎么写，嵌套、任务列表和列表里塞内容|列表怎么写]] → · 路线图：[[Markdown 语法总览]]

把文字包在一对符号里，它就换个样子。这是 Markdown 用得最频繁的一组语法。

## 一张表先看全

| 想要什么 | 写法 | 效果 |
| --- | --- | --- |
| **粗体** | `**粗体**` 或 `__粗体__` | **粗体** |
| **斜体** | `*斜体*` 或 `_斜体_` | *斜体* |
| **粗斜体** | `***粗斜体***` | ***粗斜体*** |
| **删除线** | `~~删除线~~` | ~~删除线~~ |
| **高亮** | `==高亮==` | ==高亮== |
| **下划线** | `<u>下划线</u>` | <u>下划线</u> |
| **上标** | `X<sup>2</sup>` | X<sup>2</sup> |
| **下标** | `H<sub>2</sub>O` | H<sub>2</sub>O |
| **按键** | `<kbd>Ctrl</kbd>` | <kbd>Ctrl</kbd> |

前面五种是 Markdown 原生（或 Obsidian 扩展）的写法，后面四种是 HTML——因为标准 Markdown 里根本没有下划线和上下标这回事。

## 粗体和斜体

两种写法都行，挑一个用到底就行：

```md
**这是粗体**，__这也是粗体__。
*这是斜体*，_这也是斜体_。
```

↓ 渲染出来是这样：

**这是粗体**，__这也是粗体__。
*这是斜体*，_这也是斜体_。

为什么要两套？纯粹是历史原因，做规范的时候两套都写进去了。用 `**` 和 `*` 的人更多一些，因为打字方便。

**嵌套也支持**：

```md
**这段话是粗的，_这几个字是斜的_**
```

↓ 渲染出来是这样：

**这段话是粗的，_这几个字是斜的_**

## 删除线

一对波浪号：

```md
~~这句话被划掉了~~
```

↓ 渲染出来是这样：

~~这句话被划掉了~~

它最适合用在"这句话原本是错的，但我留着给你看"这种场合。比如记录踩坑过程时，保留错误的做法并划掉，比直接删掉更有价值。

## 高亮

一对等号：

```md
==这是重点==
```

↓ 渲染出来是这样：

==这是重点==

注意：**高亮 `==` 不是标准 Markdown**，它是 Obsidian 的方言（GitHub 上不认）。但这个站点实测支持，所以尽管用。

高亮在亮色和暗色主题下都会自动换成合适的颜色，不用担心看不清。

## 下划线、上下标、按键

这几个标准 Markdown 管不了，直接写 HTML 标签：

```md
<u>下划线</u>、
X<sup>2</sup>、
H<sub>2</sub>O、
按 <kbd>Ctrl</kbd> + <kbd>C</kbd> 复制
```

↓ 渲染出来是这样：

<u>下划线</u>、X<sup>2</sup>、H<sub>2</sub>O、按 <kbd>Ctrl</kbd> + <kbd>C</kbd> 复制

> [!warning] `^2^` 和 `~2~` 不管用
> 有些地方（比如某些 wiki 系统）用 `^2^` 表示上标、`~2~` 表示下标。**这个站点不支持这两种写法**，实测会原样显示出来。另外 `^` 在 Obsidian 里还是"块 ID"的标记符号，乱用容易出意外。老老实实用 `<sup>` / `<sub>`。

## 想让符号原样显示

如果你的正文里真的要写一个 `*` 或者 `==`，它可能被当成格式标记吃掉。

解决办法是在前面加**反斜杠**转义：

```md
\*这两个星号不会变成斜体\*
```

↓ 渲染出来是这样：

\*这两个星号不会变成斜体\*

常见需要转义的符号：

| 符号 | 转义写法 | 不转义会怎样 |
| --- | --- | --- |
| `*` | `\*` | 变成斜体 |
| `_` | `\_` | 变成斜体 |
| `` ` `` | `` \` `` | 变成行内代码 |
| `~~` | `\~~` | 变成删除线 |
| `==` | `\==` | 变成高亮 |
| `#` | `\#` | 变成标题 |
| `>` | `\>` | 变成引用 |
| `[[` | `\[\[` | 变成双链 |

## 什么时候该用哪种强调

强调是给人看的，用多了等于没用。几个习惯：

**一篇文章里加粗不超过几处。** 全篇都是重点，读者就找不到重点了。

**高亮比加粗更"吵"。** 高亮适合标"这一句是关键结论"，加粗适合标"这个词很重要"。

**别用斜体写大段中文。** 中文没有真正的斜体字形，渲染出来是把字"掰歪"，看着很别扭。中文想强调就用加粗。

**删除线别用来表示"不重要"。** 它的语义是"这原本是那样，现在不是了"。想表示不重要就直接不写。

## 常见坑

**符号没配对**

`**这是粗体` 少写一半，就不会生效，而且可能把后面一整段都吞进去。

**符号和文字之间加了空格**

`** 这样 **`（星号内侧有空格）在部分渲染器下不生效。**贴着文字写**：`**这样**`。

**一个 `*` 想表示乘号**

`2 * 3` 里的星号，如果同一行还有别的 `*`，可能被当成斜体。想保险就写 `2 \* 3`，或者用 `×`。

**下划线在单词中间**

`snake_case_name` 中的 `_` 有可能被当成斜体标记。写代码、变量名、文件名时，**用行内代码包起来**最保险：`` `snake_case_name` ``。关于行内代码见 [[05-代码怎么展示，行内代码、语法高亮和嵌套反引号|代码怎么展示]]。
