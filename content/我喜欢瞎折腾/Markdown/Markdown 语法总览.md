# Markdown 语法总览

这一组共 13 篇，是**按顺序排好的**：从"完全没写过 Markdown"开始，一路到"某种写法为什么不生效"。

每一篇的开头都有一行导航：

> 系列第 N / 13 篇 · 上一步：上一篇 · 下一步：下一篇 → · 路线图：回到这一页

所以你只要打开第 1 篇，一路点"下一步"就能顺着读完，随时点"路线图"回到这里看全局。

已经会写、只是某个语法卡住了，就直接在下面四个阶段里挑那篇看。

## 怎么用这组笔记

| 你现在是什么情况 | 怎么读 |
| --- | --- |
| 完全没写过 Markdown | 从第一阶段第 1 篇开始，按顺序读。前三篇读完就能写东西了 |
| 会写一点，但排版总是不对 | 先看第 1 篇（换行），这是最多人卡住的地方，然后再挑需要的 |
| 某个具体语法不会写 | 直接在下面表格里找，每篇都写了"学完你能做什么" |
| 照着网上教程写却没效果 | 直接看第 13 篇 |

一个提醒：前三篇（换行、标题、文字强调）看着最"简单"，但也是最容易出错的。尤其**换行**，几乎所有人在上面栽过跟头，别跳过去。

## 三个环境的差异

同一个文件，在不同地方看，有些行为是不一样的。最容易踩的就是换行：

| 环境 | 只按一次回车 | 由什么决定 |
| --- | --- | --- |
| Obsidian（默认） | 换行 | 设置里的 Strict line breaks，默认不勾 |
| GitHub / 标准 Markdown | 合并 | 规范本身就是这么定的 |
| 这个站点（当前配置） | 换行 | `quartz.config.yaml` 里的 `hard-line-breaks` 插件，已开启 |

完整解释见 [[01-换行到底怎么回事，回车、两空格、空行有什么区别|换行到底怎么回事]]。

## 这个库的写法习惯

写笔记时遵守这几条，会让笔记在两边看起来都正常。

**一行一句话。**这个站点是硬换行，你在源码里回车，页面上就真的换行。不想让读者看到换行，就别回车。

**想分段就空一行。**段落之间有空隙是浏览器给的，不是你敲出来的。

**笔记之间用双链。**`[[笔记名]]` 比手写路径好——改名、移动文件都不会断，还能生成反向链接。

**属性区只填 description。**`title` / `aliases` / `tags` 留空，也不要自己加字段。详见 [[10-Frontmatter 属性区和标签|Frontmatter 属性区]]。

**能列表格就别写一大段。**并列对比、参数罗列，表格扫一眼就清楚，比段落好读。

**该配图就配图。**元件长什么样、引脚在第几脚、线怎么连，这类内容光靠文字讲不明白。

## 改完怎么看效果

这个站点是静态网站，改完笔记或配置都要**重新构建**才会反映到网页上：

```bash
npx quartz build
```

想在发布前先看看效果，就构建到临时目录：

```bash
npx quartz build -o 临时目录名
```
