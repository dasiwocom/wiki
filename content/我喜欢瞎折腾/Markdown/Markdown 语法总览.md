| 小标题 | `##` `###`（最多六个 `#`） |

## 三个环境的差异

同一个文件，在不同地方看，有些行为是不一样的。最容易踩的就是换行：

| 环境 | 只按一次回车 | 由什么决定 |
| --- | --- | --- |
| Obsidian（默认） | 换行 | 设置里的 Strict line breaks，默认不勾 |
| GitHub / 标准 Markdown | 合并 | 规范本身就是这么定的 |
| 本站（当前配置） | 换行 | `quartz.config.yaml` 里的 `hard-line-breaks` 插件，已开启 |

完整解释见 [[换行到底怎么回事，回车、两空格、空行有什么区别]]。

## 这个库的写法习惯

写笔记时遵守这几条，会让笔记在两边看起来都正常：

**一行一句话。**本站是硬换行，你在源码里回车，页面上就真的换行。不想让读者看到换行，就别回车。

**想分段就空一行。**段落之间有空隙是浏览器给的，不是你敲出来的。

**笔记之间用双链。**`[[笔记名]]` 比手写路径好——改名、移动文件都不会断，还能生成反向链接。

**属性区只填 description。**`title` / `aliases` / `tags` 留空，也不要自己加字段。详见 [[Frontmatter 属性区和标签]]。

**能列表格就别写一大段。**并列对比、参数罗列，表格扫一眼就清楚，比段落好读。

**该配图就配图。**元件长什么样、引脚在第几脚、线怎么连，这类内容光靠文字讲不明白。

## 改完怎么看效果

本站是静态网站，改完笔记或配置都要**重新构建**才会反映到网页上：

```bash
npx quartz build
```

想在发布前先看看效果，就构建到临时目录：

```bash
npx quartz build -o 临时目录名
```
