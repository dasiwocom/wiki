# 代码跑不对，先查这几种

JavaScript 出错会报错，比 HTML 和 CSS 好查。前提是会看那些红色的字。

## 报错长什么样

```text
Uncaught TypeError: Cannot read properties of null (reading 'value')
    at app.js:12
```

三段信息：

| 部分 | 含义 |
| --- | --- |
| `Uncaught TypeError` | 错误类型，`Uncaught` 表示没人捕获它 |
| `Cannot read properties of null` | 具体原因 |
| `at app.js:12` | 出错的文件和行号，点一下能直接跳到源码 |

**先看最后一行找位置，再看中间那句话理解原因。**

## 常见的几类错误

**① 读到 undefined 或 null 的属性**

```text
Cannot read properties of undefined (reading 'name')
Cannot read properties of null (reading 'value')
```

意味着"你要读的这个东西根本不存在"。

最典型的场景：

```javascript
document.querySelector("#btn").addEventListener("click", ...);
```

元素没找到，`querySelector` 返回 `null`，接着读 `.addEventListener` 就崩了。

排查：在控制台里手敲一遍那个选择器，看返回什么。返回 `null` 就是选择器写错了，或者元素还没解析出来（脚本要加 `defer`）。

**② 调用了不存在的函数**

```text
document.getElementByID is not a function
```

大小写打错了（应该是 `getElementById`），或者拼错了。报错里那个名字，仔细看一遍。

**③ 变量不存在**

```text
myVar is not defined
```

三种可能：名字拼错、忘了声明、作用域不对（变量声明在别的函数里）。

**④ 类型不对**

```text
arr.push is not a function
```

说明 `arr` 不是一个数组。可能是 `null`、`undefined`，或者是个字符串。

```javascript
const arr = getData();   // 你以为返回数组，实际返回了对象
arr.push(1);             // 崩
```

查的办法是 `console.log(arr)` 看一眼真实的值——**这一步能解决一半的问题**。

**⑤ 死循环**

页面卡住、不响应、控制台刷屏。多半是 `while` 忘了改条件，或者循环里往数组里又 push。

## 类型转换造成的"不报错但结果不对"

这类没有红字，只能靠打印。

```javascript
"1" + 1        // "11"，不是 2
"5" - 1        // 4
[] + {}        // "[object Object]"
[1,2] == "1,2" // true
```

**输入框拿到的值永远是字符串。**

```javascript
const a = input1.value;    // "5"
const b = input2.value;    // "3"
console.log(a + b);        // "53"  ← 不是 8
```

改成 `Number(a) + Number(b)`。

## 异步造成的顺序错觉

```javascript
let result = [];

fetch("/api/list")
  .then(res => res.json())
  .then(data => { result = data; });

console.log(result);   // []  ← 请求还没回来
```

代码没错，是**时机不对**。

处理办法：把依赖这个数据的代码放进 `.then()` 或者 `await` 之后。

```javascript
const res = await fetch("/api/list");
const result = await res.json();
console.log(result);   // 现在有值了
```

## this 造成的静默失败

```javascript
const obj = {
  count: 0,
  start() {
    setInterval(function () {
      this.count++;   // this 不是 obj，也不报错，就是不动
    }, 1000);
  }
};
```

这种情况不报错，`this.count` 变成 `NaN` 或者报"不能给 undefined 赋值"。

一律把回调改成箭头函数。

## 调试的三种手段

**① `console.log`，但别只打印值**

```javascript
console.log("user 现在是:", user);
console.log({ user, id, list });        // 一次打印多个
console.table([{a:1},{a:2}]);           // 数组/对象表格化，超好用
console.log("到这里了 1");               // 在流程里撒标记，看走到哪一步断的
```

`console.table` 打印对象数组的时候，比 `console.log` 清楚十倍。

**② 断点**

在浏览器 F12 的 Sources 面板里打开你的 js 文件，点行号左边就能下断点。

刷新页面，代码执行到那里会停下来，这时候右侧能：

- 看当前所有变量的值（Scope 面板）
- 一行一行往下走（Step over）
- 把鼠标放到任意变量上看它的值

**复杂逻辑用断点，别用 `console.log` 堆。** 它比打印强的地方是：你能看到执行到这一刻的完整现场。

想在某条件成立时才停：

```javascript
debugger;   // 代码执行到这一行会自动停（前提是开了 F12）
```

**③ 二分法定位**

代码很长不知道哪一步坏的，就在中间打印一下。结果不对，问题在前半段；结果对的，问题在后半段。几次就能缩到几行。

## 一个排查顺序

1. **看控制台有没有红字**。有就点进去看行号，九成问题直接定位。
2. **把你以为的值打印出来**。`console.log` 你怀疑的那个变量，看它到底是什么。
3. **看类型**。`console.log(typeof x, x)`，很多时候是"字符串当数字用了"。
4. **看顺序**。涉及网络请求、定时器的，先确认执行顺序对不对。
5. **看是不是 `null`**。找元素的代码返回 `null` 是最常见的一类。

**永远不要看着代码猜。** 打印出来看一眼，比想十分钟快。
