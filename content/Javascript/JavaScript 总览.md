# JavaScript 总览

这一组共 15 篇，按顺序排好了：从"代码写在哪儿、怎么试"开始，到"跑不对怎么查"。

前 10 篇是纯语言（变量、判断、循环、函数、数组、对象），从第 11 篇开始真正碰页面（找元素、绑事件、表单、发请求）。

每一篇的末尾都有一行导航，打开第 1 篇一路点"下一步"就能顺着读完，随时点"路线图"回到这里。

## 怎么用这组笔记

| 你现在是什么情况 | 怎么读 |
| --- | --- |
| 完全没写过代码 | 从第 1 篇顺着读。前 6 篇读完，简单的小工具就能自己写了 |
| 学过别的语言（C、Python） | 第 1、2、3 篇快速过，重点看第 3 篇的 `==` 和 `===`、第 7 篇的 `this`，然后跳到第 11 篇 |
| 只想要页面能互动 | 第 1 篇（怎么跑起来）→ 第 11 篇（DOM）→ 第 12 篇（事件），做完这三篇就能加交互了 |
| 代码跑不对 | 直接看第 15 篇，对着报错找原因 |

一个提醒：**一半的学习时间应该花在浏览器的控制台里**，不是在读上。

按 `F12`，切到 Console，把每一篇里的代码敲进去跑一遍。看十遍不如敲一遍。

## 写 JavaScript 的几条习惯

这几条能省掉大量莫名其妙的 bug。

**默认用 `const`。** 确实要改才换 `let`，永远别用 `var`。

**永远用 `===`。** 只有判断 `x == null`（同时匹配 `null` 和 `undefined`）是例外。

**每句写分号。** 靠自动插入分号省下来的那几个字，不值得换来一整类诡异的 bug。

**先 `console.log` 你看不懂的那个值。** 别盯着代码猜，打印出来一眼就清楚了。

**涉及网络和定时器的代码，先想清楚执行顺序。** 一半的"怎么是 undefined"都是这个问题。

**DOM 操作别放在循环里。** 先在内存里拼好，再一次性插进去。

**用户输入不可信。** 往页面里写用户给的内容，一律用 `textContent` 而不是 `innerHTML`。

**前端校验只是体验，后端校验才是安全。** 前端的验证能被人绕过，这句要记住。

**出错的地方一定要有提示。** 请求失败了页面上要显示"加载失败"，不能只在控制台里悄悄报错——用户看不到控制台。
