# 异步，等结果回来再往下走

JavaScript 里最反直觉的一章：代码不一定是按你写的顺序执行的。

## 同步和异步

同步就是"一句一句往下走，每句做完才做下一句"。

```javascript
console.log("1");
console.log("2");
console.log("3");
// 1 2 3
```

异步是"这件事要花时间，我先不等你，回头再说"。

```javascript
console.log("1");

setTimeout(() => {
  console.log("2");
}, 1000);

console.log("3");

// 输出顺序：1 3 2
```

`setTimeout` 表示"1000 毫秒后执行这个函数"，但**它不会卡住后面的代码**。

所以"3"先打印，一秒后"2"才出来。

## 为什么必须这样

因为浏览器里只有一个线程。如果发一个网络请求要等三秒，这三秒里什么都干不了——页面卡住、点不动、滚不了。

所以耗时的操作（网络请求、读文件、定时器）一律做成异步，先挂起来，等好了再执行。

**你会遇到的所有"为什么这里拿到的是 undefined"，几乎都是异步造成的。**

```javascript
let data;

fetch("/api/user")
  .then(res => res.json())
  .then(json => { data = json; });

console.log(data);   // undefined  ← 这时候请求还没回来
```

## 回调：最早的写法

```javascript
getUser(id, function (user) {
  getOrders(user.id, function (orders) {
    getOrderDetail(orders[0].id, function (detail) {
      console.log(detail);
    });
  });
});
```

一层套一层，嵌套三四层就看不清了，俗称"回调地狱"。

## Promise：把嵌套拍平

```javascript
getUser(id)
  .then(user => getOrders(user.id))
  .then(orders => getOrderDetail(orders[0].id))
  .then(detail => console.log(detail))
  .catch(err => console.error("出错了", err));
```

`.then()` 里返回什么，就会传给下一个 `.then()`。

`.catch()` 捕获这整条链上任何一步的错误。

Promise 有三个状态：

| 状态 | 意思 |
| --- | --- |
| `pending` | 还没结果 |
| `fulfilled` | 成功了，有值 |
| `rejected` | 失败了，有原因 |

状态一旦定下来就不会再变。

## async/await：看起来像同步

```javascript
async function showDetail() {
  try {
    const user = await getUser(id);
    const orders = await getOrders(user.id);
    const detail = await getOrderDetail(orders[0].id);
    console.log(detail);
  } catch (err) {
    console.error("出错了", err);
  }
}
```

`await` 的意思是"等这个 Promise 出结果，再把值给我"。

函数前面加 `async`，里面才能用 `await`。

**读起来和同步代码一样**，这是它最大的好处——写异步逻辑时不用在脑子里画链子了。

三条规则：

- `async` 函数的返回值自动变成 Promise
- `await` 只能写在 `async` 函数里（模块顶层也可以）
- 错误用 `try...catch` 捕获，就像同步代码一样

## 拿数据：fetch

```javascript
async function loadUsers() {
  try {
    const res = await fetch("/api/users");

    if (!res.ok) {
      throw new Error(`请求失败：${res.status}`);
    }

    const users = await res.json();

    render(users);
  } catch (err) {
    console.error(err);
    showError("加载失败，请重试");
  }
}
```

三个容易踩的地方：

**① `fetch` 只有在网络断了才 reject。** 服务器返回 404、500 也算"请求成功"，所以必须自己检查 `res.ok`。

**② 要 `await` 两次。** 第一次等响应头，第二次等响应体：

```javascript
const res = await fetch(url);
const data = await res.json();      // 这一步才是真正把数据读完
```

**③ 永远要处理失败。** 网络断了、接口挂了，用户得知道发生了什么。

## 不要串着等

三个互不依赖的请求，这样写要花三份时间：

```javascript
const a = await fetchA();   // 等 1 秒
const b = await fetchB();   // 再等 1 秒
const c = await fetchC();   // 再等 1 秒，一共 3 秒
```

让它们同时发：

```javascript
const [a, b, c] = await Promise.all([
  fetchA(),
  fetchB(),
  fetchC()
]);   // 一共 1 秒
```

`Promise.all` 要等全部成功；任何**一个失败就整体失败**。

想"谁失败都不影响别的"，用 `Promise.allSettled`。

## 另外两个组合器

```javascript
// 谁的先回来用谁
const fastest = await Promise.race([fetchA(), fetchB()]);

// 等所有结束，不管成功失败，都拿到结果
const results = await Promise.allSettled([fetchA(), fetchB()]);
```

## 一个按钮的实际写法

```javascript
const btn = document.querySelector("#load");

btn.addEventListener("click", async () => {
  btn.disabled = true;
  btn.textContent = "加载中…";

  try {
    const res = await fetch("/api/list");
    const data = await res.json();
    render(data);
  } catch (err) {
    console.error(err);
  } finally {
    btn.disabled = false;
    btn.textContent = "加载";
  }
});
```

`finally` 里的代码**无论成功失败都会执行**，用来收尾最合适——比如把按钮恢复原状。

不加它的话，请求失败了按钮会一直卡在"加载中"。

## 顺带说一句：定时器不是精确的

```javascript
setTimeout(fn, 1000);
```

这行代码的意思是"至少 1000 毫秒后执行"，不是"正好 1000 毫秒"。

如果主线程正忙（比如有个大循环在跑），回调还得排队等。所以别用 `setTimeout` 做精确计时。

要周期性执行用 `setInterval`，记得在不需要的时候清掉：

```javascript
const timer = setInterval(fn, 1000);
clearInterval(timer);   // 不停掉它会一直跑
```
