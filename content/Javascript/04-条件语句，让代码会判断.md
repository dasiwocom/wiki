# 条件语句，让代码会判断

程序和人不一样的地方就是：它会自己判断该走哪条路。

## if

```javascript
let age = 20;

if (age >= 18) {
  console.log("成年了");
}
```

括号里放条件，条件为真就执行花括号里的代码。

## if...else

```javascript
let age = 15;

if (age >= 18) {
  console.log("成年了");
} else {
  console.log("未成年");
}
```

两条路必走一条。

## else if：多分支

```javascript
let score = 85;

if (score >= 90) {
  console.log("优秀");
} else if (score >= 80) {
  console.log("良好");
} else if (score >= 60) {
  console.log("及格");
} else {
  console.log("不及格");
}
```

执行时从上往下，**第一个成立的分支执行完就跳出**，后面的不再判断。

所以顺序很重要。下面这段是错的：

```javascript
if (score >= 60) {
  console.log("及格");
} else if (score >= 90) {   // 永远走不到这里
  console.log("优秀");
}
```

`>= 90` 的也满足 `>= 60`，会先被第一个分支截住。

**条件要从窄到宽排**，或者从大到小排。

## 花括号不能省

```javascript
if (a) 
  console.log("一");
  console.log("二");   // 这行永远都会执行！
```

不写花括号的时候，`if` 只管紧跟着的那一条语句。

第二行看起来像在 `if` 里面，实际上在外面。这种 bug 特别难找，所以**永远写花括号**，哪怕只有一行。

## 条件怎么写

`if` 后面括号里的东西会被转成布尔值（真假值），规则见 [[03-运算符和比较，以及 == 和 === 的区别|上一篇]]。

```javascript
if (name) { }              // 只要不是空字符串就进来
if (list.length) { }        // 数组不为空
if (list.length === 0) { }  // 数组为空
if (user?.name) { }         // 存在才判断
```

注意 `if (list)` 永远是 `true`，因为数组本身（哪怕是空的）是真值。想判断空数组要用 `list.length`。

## switch

当判断的是"某个值等于哪几种情况"时，`switch` 比一串 `else if` 清楚：

```javascript
let day = "周二";

switch (day) {
  case "周一":
    console.log("开始上班");
    break;
  case "周六":
  case "周日":
    console.log("休息");
    break;
  default:
    console.log("普通工作日");
}
```

几个要点：

**`switch` 用的是全等比较（`===`）**，`case 1` 匹配不上字符串 `"1"`。

**`break` 不能漏。** 漏了会"贯穿"——从匹配到的那个 `case` 开始，一直往下执行，直到遇到 `break`。

上面例子里的 `case "周六":` 后面没写代码也没写 `break`，是有意为之：让它贯穿到 `"周日"` 那一段，两个条件共用一套处理。这是合法用法，但要看清楚再写。

**`default` 是所有 case 都不匹配时走的**，位置可以放最后（习惯上）。它不需要 `break`。

## switch 还是 if

| 判断条件 | 用什么 |
| --- | --- |
| 一个值等于几种固定情况 | `switch` |
| 范围判断（`> 90`、`< 60`） | `if...else if` |
| 条件比较复合（`a && b`） | `if` |
| 只有两三种情况 | `if` 更短 |

`switch` 的适用面其实很窄，日常写 `if` 更多。

## 嵌套太深怎么办

判断套判断，很快就读不动了：

```javascript
function pay(user, amount) {
  if (user) {
    if (user.balance >= amount) {
      if (!user.frozen) {
        return "支付成功";
      } else {
        return "账号被冻结";
      }
    } else {
      return "余额不足";
    }
  } else {
    return "请先登录";
  }
}
```

这段能跑，但看的时候要在脑子里爬四层。

**提前 return** 是通用的解法——把不满足条件的情况先挡掉：

```javascript
function pay(user, amount) {
  if (!user) return "请先登录";
  if (user.frozen) return "账号被冻结";
  if (user.balance < amount) return "余额不足";
  return "支付成功";
}
```

逻辑一模一样，但主流程是平的，一眼能读完。

判断里还有 `return`、`continue`、`break` 的时候，都可以用这个办法。

**判断越早结束，代码越好读。**
